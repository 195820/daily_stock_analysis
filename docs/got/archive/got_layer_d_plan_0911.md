### 2.1 `divergent` 分支仍 0 触发，且阈值不可观测（P0-1）

**唯一生产点**：`aggregator.py:1494`。**消费者 3 处**：`:1284`（`composite -= 15`）、
`:1773`（`_is_hard_exclude`）、`:3551`（`capital_stance = "rejected"`，`:3580` 消费）。
另 3 处展示（`archive.py:219/240`、`aggregator.py:3760`）。

**实测 1 —— 归档口径**：30 个有 `confirmed_sectors` 的归档日中，`capital_check` 只出现
`neutral` / `aligned`，**`divergent` 一次都没有**（含 `74c0534` 之后的 6 个交易日
0903/0904/0907/0908/0909/0910）。

**实测 2 —— 消费侧口径**（更强，不受硬拒绝幸存者偏差影响）：

```
portfolio_decision.json → mainline_endurance[].capital_stance
全期分布：{missing: 19, passed: 3}        # rejected = 0
```

这正是 0902 报告自己预言的后果（「`capital_stance` 永远不可能为 `rejected`」），
**九天无人复核**。

**实测 3 —— 主因不是 `min()`，是「阈值总体 ≠ 判定总体」**：

`_divergent_threshold`（`:1407-1420`）在**全市场 ~400 个板块**的净额分布上取最差 5% 分位，
却只用在 **~15 个 `confirmed_sectors`** 上。而确认板块是被 Node 2 挑出的强板块，
与「全市场最差 5%」**反向选择**。两个反例：

| 日 | 板块 | 净流出 | `capital_detail` 文案 | 结论 |
|---|---|---|---|---|
| 0901 | 半导体 | −167.0 亿 | `半导体净流出167.0亿(全量)` | 走 `else → neutral`（`:1499`），即 `amount ≥ 阈值` |
| 0904 | 固态电池 | −112.0 亿 | `固态电池净流出112.0亿(全量)` | 同上 ⇒ 当日阈值已 ≤ −112 |

`:1419-1420` 的无条件 `min(阈值, −80)` 只在**平静日**起作用：0903（最大 0.5 亿）、
0907（16.8 亿）、0908（0.8 亿）、0910（44.1 亿）都被钉在 −80，
此时「最差 5% 分位」相对水位的自适应能力被完全放弃。

> `★ Insight ─────────────────────────────────────`
> **报告识别了两个混杂因子，修复只去了一个。** 报告原文说「绝对金额同时编码了『板块体量』
> 与『市场水位』两个无关因子」——改成分位后，**水位**被消掉了，**体量**还在：
> 全市场最差 5% 由大板块主导（0901 的 3D打印 −83.6 / MLCC −65.5 / 半导体 −167.0 全是大板块），
> 而判定对象是小样本强板块。改判据的人把「总体」当成了一个可以直接替换的常量，
> 没有意识到判定总体与被判定总体必须同源。
> `─────────────────────────────────────────────────`

**实测 4 —— 阈值不可观测**：阈值唯一被持久化的位置，是 `divergent` 分支自己的
消息文本（`:1494-1497` 的 `居全市场最差5%（阈值-XX亿）`）。**只在触发时才可见 = 不可观测**。
`capital.json` 只落 `top_concepts`（5 条）+ `top_industries`（3 条），全量分布不在归档里。

> **幸存者偏差声明**：`_is_hard_exclude`（`:1773`）在 `late_stage` / `mature_exhausted`
> 时会因 `divergent` 排除该板块，故「归档口径 0 触发」不能 100% 排除
> 「触发过但被硬拒绝挤掉」。实测 2 的消费侧证据（`mainline_endurance` 不受该路径影响）与之独立且一致。

### 2.3 `associated_sectors` 恒空 → 三处结构性失效（P1-4）**← 本层最重**

**生产端三个数据路径，没有一个填这个字段**：

| 路径 | 位置 | 实际 |
|---|---|---|
| 东财千股千评 | `sentiment_analysis.py:792` | `associated_sectors=[]` 硬编码 |
| 雪球 | `sentiment_analysis.py:822` | `associated_sectors=[]` 硬编码 |
| NGA | `sentiment_analysis.py:543-551` | 根本没传该字段（走 Schema 默认 `[]`） |

于是唯一的生产者 `_extract_hot_sectors(sentiment)`（`aggregator.py:3322-3327`，
遍历 `stock.associated_sectors`）**永远返回 `[]`**。它有三个消费者，全部因此失效：

**① `sentiment_check` 恒 `low`** —— `_cross_check_sentiment`（`:1624-1625`）第一行即

```python
if not hot_sectors:
    return "low", "无热榜数据"
```

0910 实测：`sentiment_detail = {'无热榜数据': 32}`（32/32）、`sentiment_check = {'low': 32}`（32/32）。

→ 这是 **B 层 B1 的根因链起点**。完整链条：
`associated_sectors=[]` → `sentiment_check` 恒 `low` → B1（四维调整项近空）
→ `ρ(tech_score, composite_score) = 0.985` → C 层 C3（M4 三条红线只有一个自由度）。

**② 埋伏闸门 G3（拥挤度黑名单）恒不触发** —— `_check_crowded_blacklist`（`:2890-2907`，`@staticmethod` 在 `:2889`）
遍历 `hot_sectors`，恒返回 `False`。

**③ 埋伏闸门 G2 的注意力闸恒不触发** —— `_check_anti_top_buy`（`:2866-2872`）：

```python
match_count = sum(1 for hot in hot_sectors if self._fuzzy_match(sector_name, hot))
if match_count >= 3:      # 恒为 0，永不成立
```

而 `_run_ambush_gates` 的 docstring（`:1987`）写的是「**4 层闸门**流水线
（★★★利空 + 防买顶 + 拥挤度 + 吸筹确认）」——**实际活着的是 2 个半**（G1 全 + G4 全 + G2 半；**G3 死**）：

| 闸 | 状态 | 依据 |
|---|---|---|
| G1 ★★★利空 | **活** | `:2005-2008` `return False`，真否决 |
| G2 防买顶 | **只剩半边** | `_check_anti_top_buy` docstring（`:2859`）自述「防买顶**双闸**：注意力闸 + 已发酵检查」。**注意力子闸**（`:2866-2872`）依赖 `hot_sectors` → **死**；**已发酵子闸**（`:2874-2885`）**只依赖 `events` + `today`、不碰 `hot_sectors`** → **活**，仍在 `return False` 否决位 |
| G3 拥挤度黑名单 | **死** | `_check_crowded_blacklist`(`:2890-2907`) 遍历 `hot_sectors`(`:2903`)，恒空时循环零次 ⇒ 落到 `:2907 return False`，**恒 `False`** |
| G4 吸筹确认 | **活** | `:2021`，唯一可被 Agent 提名救回 |

⚠️ **2026-09-11 修订**：本节原写「**实际只有 2 层活着**（G1 利空 + G4 吸筹）」「**所有否决权都压在 G4 上**」——
**两处均过度断言**。原判据「`_check_anti_top_buy` 依赖 `hot_sectors`」漏了该函数内的**第二个**子闸；
`:2010` 的注释亦自述「闸门 2: 防买顶**双闸**（真否决，提名不可覆盖）」。
⇒ **不可被提名救回的真否决，结构上有三处**：G1、G2 的已发酵子闸、G3。
（**G4 不算**：它是唯一可被 Agent 提名救回的那一个，见 `:2021`。）

⚠️ **但三处的失效性质不同，不可同列**（2026-09-11 第三轮复核补）：
- **活着的真否决只有两处** —— G1 与 G2 的**已发酵子闸**。二者都**不碰 `hot_sectors`**，
  样本期 0 触发属**偶然**（数据源修不修它们都在工作）。
- **G3 是结构性失效** —— `_check_crowded_blacklist`(`:2890-2907`) 的 `for hot in hot_sectors`(`:2903`)
  在 `hot_sectors` 恒空时**循环零次**，直接落到末尾的 `return False`(`:2907`) ⇒ **恒返回 `False`**。
  其 0 触发是**必然**，原括注「结构在、样本内 0 触发」**对 G3 不成立**，已删。

⇒ 归档扫描（2026-09-11，**含正对照**）：真实 reason 字面量 `★★★利空否决`(:2008) / `防买顶否决`(:2015) /
`拥挤度黑名单（多只个股上热榜，来晚了）`(:2019) / `上热榜（注意力已过高）`(:2872) /
`行情可能已提前走完`(:2885) **全部 0 命中**；而同通道的 `吸筹观察`(:2031) **命中 12 个归档日**。
正对照排除了「reason 根本不落盘」这一竞争解释，**但这 5 个字面量不能一并归为「样本期未触发」**：

| reason 字面量 | 闸 | 0 命中的性质 |
|---|---|---|
| `★★★利空否决`(:2008) | G1 | **样本期未触发**（活） |
| `行情可能已提前走完`(:2885) | G2 已发酵子闸 | **样本期未触发**（活） |
| `上热榜（注意力已过高）`(:2872) | G2 注意力子闸 | **结构性不可达**（依赖 `hot_sectors`，须修 `associated_sectors` 才可能复活） |

| `防买顶否决`(:2015) | G2 总出口 | **两者叠加**（注意力子闸结构性不可达 + 已发酵子闸样本期未触发） |

原表述（「实际只有 2 层活着」）把**活的**与**死的**混同；而「5 个字面量全部 0 命中」若不加区分，
又会把**结构性不可达**（`:2872`/`:2019`）与**样本期未触发**（`:2008`/`:2885`）混同 ——

## 3. 根因

**「自述 ≠ 验收」在四个载体上重演**：

| 载体 | 自述内容 | 缺的验收动作 |
|---|---|---|
| 0903 §8.1 六条转正红线 | 转正条件 | 红线从未被实测（→ C 层） |
| 0902 报告 15 项 | 已修复 | 修复状态从未被实测（→ 本层） |
| `data_quality.missing` | `hot_stocks_sectors_empty` ×6 天 | 报了没人处理（→ §2.3 ④） |
| `TODO: 待校准 (当前样本量: 0)` | 该阈值未校准 | 未校准的阈值照常在闸门里做否决（→ §2.4） |

**具体到本层的四个「≠」**：

- **代码存在 ≠ 分支可达** —— `divergent`（§2.1）
- **字段存在 ≠ 字段有值** —— `associated_sectors`（§2.3）
- **闸门存在 ≠ 闸门活着** —— G2 注意力闸 / G3 拥挤度黑名单（§2.3 ②③）
- **阈值存在 ≠ 阈值校准** —— `0.30` / `0.7 (样本量 0)`（§2.4）

四个「≠」的**共同形态是同一个**：**可观测性缺口**。
只要某个量不在归档里、或只在触发时才落盘、或被容量截断、或只有一个"成功"分支会写它，
那么任何「存在即生效」的推断都**不可检验**——而报告与文档恰恰一直在做这种推断。

### C.8 E 层的元结论

**E 层就是审计报告自己的「其他」家族。** 0902 报告 P2-4 骂过
「『其他』家族变成垃圾箱——风沙治理与军贸概念同组」；
而 E 层（「其他具体缺陷」）是同一形态在审计层的重演——
**12 项里 4 项后来证明归属别处或被推翻**（E1 / E7 / E8 / E9，与 §7.1 E 行、附录 C.3 同口径；
⚠️ 原写「5 项」是附录 C.3 由「5 项」改「4 项」时**漏改的本节转述**），正因为它是暂存桶、没有归属判据。

更值得注意的是：**E 层的三种形态全部是「存在 ≠ 生效」的换装**
（D 层 §3 的四个「≠」）：

| E 层形态 | 对应 D 层的「≠」 |
|---|---|
| 形状 1 存在但未启用（E4/E5/E10/E11） | **代码存在 ≠ 分支可达**、**字段存在 ≠ 字段有值** |
| 形状 2 同名不同量（E2/E6） | **名字存在 ≠ 语义唯一** |
| 形状 3 只乘不除（E3） | **数值存在 ≠ 量纲正确** |

所以 E 层不需要红线，也不需要专项——**它的每一项都是 D 层可观测性清单的实例**。
这也解释了为什么它当初会变成垃圾箱：**没有归属判据的层，必然累积成「其他」**。
