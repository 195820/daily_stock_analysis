# 修复：持仓板块漂移误卖（买入理由继承 + 家族中继匹配 + 卖出宽限）

> 状态（2026-10-06 补）：已实施（commit `20cba78`，见 backlog §4.4）；本文件仅留设计背景，后续验收口径以《docs/got/plans/入场分道与持仓延续性_总计划_20260930.md》及其合并审核为准，勿按本文重复实施。

## Context

持仓股 688598 金博股份被误判卖出（当日 portfolio_decision.json：石墨烯 composite 45 / caution / capital divergent → sector 33 分 → sell）。根因两个：

1. **买入理由未继承（板块名漂移）**：买入时按"半导体"口径评分（半导体当时是主线家族），但持仓分析时 `_reverse_lookup_stock_sector` 只做**板块名级**匹配——今日 confirmed_sectors 无"半导体"板块名（半导体家族在池内只有先进封装 92/存储芯片 90/第三代半 80 等成员板块），家族关系完全丢失，只剩石墨烯命中（fallback 路径取 boards 中强度最高者 63.7）。金博的碳基材料属半导体上游，家族口径正确（用户已确认）。
2. **卖出逻辑太简单**：纯规则匹配，板块名漂移后直接落入 `sector_role not in ("mainline","ambush")` → sell（`portfolio_decision.py:604-605`），无买入论点校验、无确认窗口。

**当日数据取证**（`data/got_daily/20260918/`）：
- 688598 efinance boards 25 个，含"半导体概念"和"石墨烯"
- `frame_group_lookup` 211 条：`半导体→AI硬件`、`石墨烯→周期资源`；`normalize_sector_name` 含 `"半导体概念"→"半导体"`
- confirmed_sectors 27 个（mainline 14 + ambush 13），AI硬件家族内最高 composite：先进封装 92（mainline）
- `SectorIntel.frame_group`（`schemas.py:714-717`）已携带家族名 → 家族→confirmed 锚点映射可从 `unified_context.confirmed_sectors` 直接构建，无需新数据源

**论文佐证**（exa 检索）：
- Shefrin & Statman 1985（doi:10.1111/j.1540-6261.1985.tb05002.x）/ Odean 1998（doi:10.1111/0022-1082.00072）：处置效应——卖出决策应基于论点失效而非纯价格/规则触发
- Ben-David & Hirshleifer 2012（SSRN 1876594）：卖出倾向应源于论点修正（belief updating），价格/规则偏离触发的是校验而非即卖
- Industry classification misfits（Rev Account Stud 2025, doi:10.1007/s11142-025-09886-4）：单一分类体系 12% misfits，跨体系（GICS+SIC）组合识别更稳——家族级（frame_group）匹配优于单一板块名匹配
- FrontierPicks 投资论点框架：thesis = falsifiable claim + invalidation trigger（事先声明的失效条件）≠ stop-loss——买入理由快照 + 失效检测的理论基础
- Bethke 2026 退出规则回测（erikbethke.com）：快触发在噪声信号上 whipsaw——确认信号 + 宽限窗口优于单日即卖
- Invesco 2024 非对称门槛（代码 `:587` 已实现）：进入 60 / 踢出 40——宽限条件沿用同一阈值口径

## Approach

三个 Fix，按依赖顺序：Fix 1（家族中继匹配，纯函数级）→ Fix 2（买入论点快照表，新表 + 读写接线）→ Fix 3（卖出宽限，消费 Fix 1/2 的家族锚点与论点记录）。所有决策写死，不留开放项。

### Fix 1：家族中继匹配（`_reverse_lookup_stock_sector` 一级半层）

**数据管道**（模式照抄 strength_lookup `:428-430`）：

1. `src/got/schemas.py` `UnifiedScoringResult`（`:959-1002`）新增两个可观测字段：

```python
sector_match_type: Optional[str] = Field(
    default=None,
    description="板块匹配方式: direct / relay / thesis / fallback / none",
)
sector_drift_grace: bool = Field(
    default=False,
    description="家族宽限标记（板块漂移但家族仍强，降级持有观察）",
)
```

2. `_score_holdings`（`portfolio_decision.py:407`）`:430` 后新增提取：

```python
frame_group_lookup = getattr(sector_context, "frame_group_lookup", {}) or {}
```

两个 `_find_stock_sector` 调用点（`:458-462`、`:493-497`）增传 `frame_group_lookup=frame_group_lookup`；`_find_stock_sector`（`:1359`）与 `_reverse_lookup_stock_sector`（`:1530`）签名各加同名 kwarg（默认 None，向后兼容测试直调）。

3. `_reverse_lookup_stock_sector` 在一级 confirmed 匹配 return（`:1602-1606`）之后、二级 ambush（`:1608`）之前插入家族中继层，实现为独立方法（保持主函数可读）：

```python
def _family_relay_match(
    self, boards: list, unified_context: UnifiedContext,
    frame_group_lookup: Dict[str, str],
) -> list:
    """家族中继匹配（Fix 1）：板块名不在 confirmed_sectors，但所属家族内有 confirmed 板块。

    板块名 → normalize → frame_group_lookup → 家族名 → 家族内 composite 最高的
    confirmed 板块作锚点（anchor）。强度取锚点 composite，sector_role/三维 check
    注入锚点值；sector_name 保留归一化后的原板块名（如"半导体"），避免误标
    "先进封装"。weight 1.2（直接主线命中 1.5 / 普通命中 1.0 之间）。
    """
```

逻辑要点（全部写死）：
- `family_anchor: dict[家族名, SectorIntel]`：遍历 `unified_context.confirmed_sectors`，按 `intel.frame_group` 分组取 composite 最高者为锚点（`_build_family_anchor_map` 抽成独立方法，Fix 3 复用）
- 遍历 boards：`canon = normalize_sector_name(board_name)`；`family = frame_group_lookup.get(canon) or frame_group_lookup.get(board_name)`；家族无锚点或已见过（`seen` 按 family 去重，同族多板块只占一个名额，对齐 D-P7 精神）→ skip
- 命中项：

```python
{
    "sector_name": canon,                  # 归一化原板块名，如"半导体"
    "sector_type": anchor.sector_type,
    "strength": anchor.composite_score * 0.85,  # 家族锚点综合分打折（问题1修正）：历史/家族锚点弱于当日直接命中，~92×0.85≈78，仍压过石墨烯 63.7
    "weight": 1.2,
    "sector_role": anchor.sector_role,     # mainline → 不再落入 :604 sell 分支
    "capital_check": anchor.capital_check,
    "news_check": anchor.news_check,
    "sentiment_check": anchor.sentiment_check,
    "is_relay": True,
    "relay_family": family,
    "relay_anchor_sector": anchor.sector_name,
}
```

- **不做二次 intel 调整**：中继 strength 已是打折后的锚点 composite（Node 6 已含交叉验证），`_adjust_score_by_sector_intel`（`:863`）对不在 intel_map 的 sector_name 原样返回 base_score——中继路径自然跳过 actionable +10 加成，避免双重计入（直接命中路径是 strength=composite 后再加 adjustment 的既有行为）。
- **weight 1.2 不稀释 sector 维度（问题1取证）**：`_find_stock_sector`（`:1414-1418`）加权平均中，当家族仅一个成员能中继（最常见）时 weight 被约掉，strength 原样进入 sector 维度。故「保守一档」不能靠 weight 实现，改由 strength ×0.85 显式打折（见上）。
- **过热降权必须继承（问题2取证，不可逃逸）**：composite_score（`aggregator.py:1505-1538`）不含 overheat——过热是 Phase 2 独立乘性惩罚。中继 sector_name（"半导体"）不在 sector_intel_map，`_compute_overheat_penalty`（`:945-946`）会 `return 1.0`，逃逸 severity 档 + `frame_group∈crowded_families` 拥挤档两层惩罚。修法见 step 5：用 `relay_anchor_sector` 查惩罚，对称继承锚点过热。锚点 composite 未扣过热，继承不会双重计入。

4. **生命周期提取接线**（`:553-574`）：中继 sector_name 不在 `sector_intel_map`，在 `elif sector_name:` 前插入锚点分支：

```python
anchor_name = stock_sector_info.get("relay_anchor_sector")
if sector_name and sector_name in sector_intel_map:
    ...  # 原逻辑不变
elif anchor_name and anchor_name in sector_intel_map:
    intel = sector_intel_map[anchor_name]   # 生命周期/过热/家族名取自锚点板块
    lifecycle_phase, lifecycle_day = intel.get('lifecycle_phase'), intel.get('lifecycle_day')
    overheat_severity, family_name = intel.get('overheat_severity'), intel.get('frame_group')
elif sector_name:
    ...  # extended_lifecycle_map 原逻辑不变
```

5. **过热降权继承接线**（`:515-524`，问题2修正）：`_score_holdings` 计算 `overheat_penalty` 处，把查惩罚用的板块名换成锚点名——中继/论点命中项携带 `relay_anchor_sector`（在 intel_map 中，含 overheat_severity + frame_group）：

```python
overheat_lookup_name = (
    stock_sector_info.get("relay_anchor_sector") or sector_name
)
overheat_penalty = self._compute_overheat_penalty(
    overheat_lookup_name, sector_intel_map, unified,
)
```

直接命中路径 `relay_anchor_sector` 为空 → 退回 `sector_name`，行为不变（回归安全）。`_compute_overheat_penalty` 是 `@staticmethod`，沿用 `self.` 前缀调用即可。

6. **reasoning 展示**（`:688-694`、`:659-686`）：
- `:689` "（板块已踢出）" 判定加 `and not is_relay` 防御（中继命中≠踢出）
- 新增中继展示分支（置于 `in_intel_map` 分支之后）：`sector_display = f"板块[{sector_name}→家族{relay_family}·锚点{anchor_name}{anchor_strength:.0f}分]"`
- 688598 预期效果：Top-3 排序中"半导体"（strength≈78, weight 1.2）压过石墨烯（63.7）成为主板块，sector 维度 ≈78×过热系数（而非虚高 92、也非误判 33），sector_role=mainline 不落入 `:604` sell 分支

### Fix 2：买入论点快照（新表 `holding_thesis_snapshots` + 全量买入写入 + 持仓读取）

复用 `ambush_position_snapshots`（`src/storage.py:1218-1254`，P4 只对埋伏买入生效）的机制思路，但普通买入也要有论点锚点。

1. **新表**（`src/storage.py`，紧跟 `AmbushPositionSnapshotRecord` 之后，照抄其 SQLAlchemy 声明模式）：

```python
class HoldingThesisRecord(Base):
    """持仓论点快照（买入理由继承）：Phase 2 全量买入时记录板块/家族锚点，
    持仓分析时板块名漂移则按家族锚点校验论点是否仍成立。"""
    __tablename__ = "holding_thesis_snapshots"
    id / symbol(String, index) / sector_name(String) / family_name(String)
    entry_date(Date) / entry_price(Float)
    composite_at_entry(Float, nullable)      # 买入时综合分
    source(String)                            # "got_buy" / "drift_watch"（Fix 3 懒建）
    drift_watch_since(Date, nullable)         # Fix 3：漂移观察起始日
    drift_family(String, nullable)            # Fix 3：观察时的家族名
    is_open(Bool, default True) / created_at / updated_at
    UniqueConstraint("symbol", "entry_date")  # 同日重跑 UPSERT，同 P4 A-P0-6
```

表自动建表（storage.py 现有 `Base.metadata.create_all` 机制覆盖新表，无迁移脚本）。

2. **写入**：`portfolio_decision.py:151` 调用点旁新增 `_write_thesis_snapshots(allocation, unified_scoring, unified_context)`，对所有 `action=="buy" and quantity_delta>0` 的 allocation 写入：
- `sector_name = scoring.sector_name`（P2-4 同款：不用 reasoning 反解析）；空则跳过（无法锚定）
- `family_name = scoring.family_name or frame_group_lookup.get(sector_name) or ""`（候选侧 family_name 可能为 None，用 `unified_context` 反查兜底：`sector_intel_map` 不含时查 frame_group_lookup——frame_group_lookup 需作为参数传入，从 sector_context 提取一次）
- 同日 UPSERT 逻辑照抄 `_write_ambush_snapshots` `:2084-2100`（自然键 symbol+entry_date）
- 失败降级：try/except 记 warning 不阻塞主流程（同 P4 `:2126-2131` 模式）

3. **读取**：`_score_holdings` `:449` 旁新增 `_load_holding_theses(positions)`：查 `is_open=True` 且 symbol 在持仓集的记录，每 symbol 取 `entry_date` 最新一条，返回 `symbol → record`。降级同 `_load_ambush_snaphots` `:2032-2034`。

4. **消费（论点校验）**：`_find_stock_sector` 结果为 **fallback（`is_fallback=True`）或 sector_name 为空** 时（即当日板块级匹配彻底失败），若论点快照存在且 `thesis.family_name` 仍在当日确认家族中（`family_anchor` 有该家族）→ 论点仍成立，构造中继型结果：

```python
{
    "sector_name": thesis.sector_name,       # 买入时锚定板块名（如"半导体"）
    "strength": anchor.composite_score * 0.75,  # 论点家族当日锚点强度打折（问题1修正）：历史论点锚点弱于当日 boards 中继（0.85），故再低一档 0.75
    "weight": 1.0,                           # 排序权重低于当日中继（1.2）；⚠ 单锚点场景 weight 会被加权平均约掉，强度差异靠上面的 0.75 折扣保证（非 weight）
    "sector_role": anchor.sector_role,
    "is_relay": True, "relay_family": thesis.family_name,
    "relay_anchor_sector": anchor.sector_name, "relay_source": "thesis",  # relay_anchor_sector 同时供 step 5 过热继承（问题2：论点路径也不逃逸过热）
}
```

**优先级写死**：当日 boards 家族中继（Fix 1）> 论点快照（Fix 2）> fallback > 空。当日数据更新鲜；若当日 boards 中继命中的家族与论点家族不同，用当日家族（论点已被市场新主线替代，属正常轮动）。
- 注：688598 等存量持仓无快照（表新建时为空），走 Fix 1 中继——Fix 2 是前向机制，从下一次买入起积累。

5. **关闭**：`_close_ambush_snapshots`（`:148`）旁新增 `_close_thesis_snapshots(allocation, portfolio)`：`action=="sell"` 的 allocation 置 `is_open=False` + `exit` 语义（复用 drift 表无 exit 字段，直接 is_open=False；reduce 保持 open）。

### Fix 3：卖出宽限（家族强度滞回 + 次日确认）

修改 `_score_holdings` 卖出判定分支（`:576-635`），核心是新增一个可单测的纯逻辑方法：

```python
def _drift_action_with_grace(
    self, symbol: str, sector_name: str, sector_strength: float,
    frame_group_lookup: Dict[str, str],
    family_anchor: Dict[str, Any],           # Fix 1 的 _build_family_anchor_map 输出
    thesis: Any,                              # HoldingThesisRecord 或 None
    today: date,
) -> tuple[str, bool]:
    """板块漂移卖出分支的宽限判定（Fix 3）。

    Invesco 非对称门槛同口径滞回（Bethke whipsaw 证据）：
    - 漂移板块所属家族锚点 composite >= 60 → hold + 置观察（首次）
    - 家族锚点 [40, 60)：观察已跨交易日 → sell；首次 → reduce + 置观察
    - 家族锚点 < 40 或无家族/无锚点 → sell（深度破位，不宽限）
    返回 (action, grace_applied)；grace_applied=True 时上游 reasoning 加 [家族宽限:家族X]。
    """
```

接线（`_score_holdings` 内）：
- 在进入 `:576` 动作判定前预构建：`family_anchor = self._build_family_anchor_map(unified)`、`thesis_map = self._load_holding_theses(positions)`
- `:581`（`not sector_name` → sell）与 `:604-605`（`sector_role not in (mainline,ambush)` → sell）两个**漂移型** sell 分支，替换为调用 `_drift_action_with_grace`：
  - 板块家族 = `frame_group_lookup.get(normalize_sector_name(sector_name))`（sector_name 为空时用论点家族）
- 宽限状态持久化到 `HoldingThesisRecord.drift_watch_since / drift_family`：`_apply_drift_watch(symbol, family, today)`——记录存在则 UPDATE，不存在则**懒建**（source="drift_watch"，entry_price=last_price，sector_name=当日匹配名）；家族锚点 ≥60 时 `drift_watch_since` 保持（持续 hold），家族转弱跨交易日才放行 sell。写库 try/except 降级（宽限判定本身不依赖写库成功——失败只影响次日确认精度，当日 action 不变）
- 非漂移分支（`:588-599` 池外强度门槛、`:606+` P4 埋伏退出、`_lifecycle_sell_signal` 止损/衰竭/过热）**一律不动**——那些是论点失效信号（FrontierPicks invalidation trigger），宽限只保护"板块名漂移"这一类纯口径噪声
- grace 命中时 `sector_drift_grace=True`、reasoning 追加 `[家族宽限:家族X，锚点Y分]`，`sector_match_type` 相应设 relay/fallback 保持实际值

### 步骤 6：`sector_match_type` 填充（可观测性）

`_score_holdings` 结果构造（`:726-751`）按 `stock_sector_info` 填：direct（sector_name 在 intel_map）/ relay（is_relay 且 relay_source 无）/ thesis（relay_source=="thesis"）/ fallback（is_fallback）/ none（sector_name 空）。`sector_drift_grace` 从 Fix 3 传入。portfolio_decision.json 落盘自动携带（UnifiedScoringResult 序列化）。

## Assumptions

- **frame_group_lookup 覆盖度**：211 条覆盖 Node 2 analyzed 板块（东财口径）；同花顺口径名（如"半导体概念"）必须先 `normalize_sector_name`——board_aliases 已含 `"半导体概念"→"半导体"`。若个别 THS 名不在别名表，中继 miss → 走原 fallback 路径，行为不劣于现状（grace 的 thesis 懒建兜底）。
- **family_anchor 复用**：`_build_family_anchor_map` 只依赖 `unified_context.confirmed_sectors`（`SectorIntel.frame_group` `:714-717` 已有字段），无新数据依赖；A6 glue 转正只替换板块评分四件套，不动 frame_group，无冲突。
- **锚点强度打折 0.85（问题1）**：家族锚点取 composite 最高成员，对只属弱子板块的漂移股偏高；且 weight 1.2 在单锚点场景被加权平均约掉、不稀释 sector 维度。故对中继 strength 显式 ×0.85，表达「历史/家族锚点弱于当日直接命中」。系数可调，但必须 <1.0。
- **过热不可逃逸（问题2）**：composite_score 不含 overheat（`aggregator.py:1505-1538`），过热是 Phase 2 独立乘性惩罚。中继继承家族 upside 就必须继承同一家族的过热 downside——用 `relay_anchor_sector` 查 `_compute_overheat_penalty`，继承 severity 档 + 家族拥挤档，无双重计入。
- **论点快照冷启动**：新表初始为空，存量持仓（含 688598）靠 Fix 1 中继 + Fix 3 懒建观察记录覆盖；前向从下一次买入开始积累完整论点。这是可接受的渐进路径，不是功能缺口。
- **`_stock_sector_map` 缓存**：`_find_stock_sector` `:1374-1391` 的实例级缓存对中继结果同样生效（同一次 run 内 sector_context 不变，缓存安全）。
- **宽限不覆盖论点失效信号**：止损/衰竭/过热/晚周期/埋伏 P4 退出（`_lifecycle_sell_signal`、`_ambush_exit_signal`）不宽限——那是 FrontierPicks invalidation trigger 的等价物，必须即卖。宽限只保护板块名漂移（口径噪声）。
- **DB 写入失败降级**：thesis 表所有写路径 try/except 降级（同 P4 模式），宽限判定当日 action 不依赖写库成功。
