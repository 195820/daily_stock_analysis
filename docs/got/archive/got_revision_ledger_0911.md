### ⚠️ 对质询 #2 的措辞更正（事实成立，但结论表述不准）

质询称达标线「**不可能成立**」——**不准**。规范成**集合相等**后它是可判定的：
修复前 `12 ≠ 14` → **FAIL**；修复后 `14 == 14` → **PASS**。这是一条好红线。
真实缺陷是**指标列写 `⊆`、达标线写「相等」，两者方向不一致**；且 `⊆` 方向是空红线
（`12 ⊆ 14` 修复前已 `True`，验证不出任何东西）。已统一为集合相等。

### ⚠️ 对质询 #13 的归因更正（D 层并未低估）

质询称 D 层「称之为历史巧合、低估了」。核查 D 层原文（附录 C.4）——**它自己就写了
`0.20 < 阈值` 数学上不可能成立**，是**同一套推导**，不存在低估；`26/26` 是它的**实测后果**，不是归因。

但质询有一个 D 层确实没说对的点，已采纳并写入：**「不可达」的根因是 `:2800` 的解析 bug，
不是结构性质**。`max_limit ≤ 0.40 ⇒ 阈值 ≤ 0.20` 只对「恒走 default 0.20」成立；
解析修好后 `stock_limit` 取到该股**所属板块**的真实上限（如 ambush `0.20×0.65×0.55×0.7 ≈ 0.050` ≪ 主线 `0.182`），
条件 `L_s < 0.5·max_limit` **成立** ⇒ **修好解析后该分支可达**。
⇒ **D-P11 是行为变更项**（触发面 = 修复后重算），不是零行为变更的可观测性项。

### 归档扫描的正对照（#5 的实测依据，2026-09-11 补）

用**真实 reason 字面量**扫 `data/got_daily/`（不是文档里的概念名）：

```
吸筹观察             (G4，已知活)          -> 12 个归档日命中   ← 【正对照】
上热榜（注意力已过高） (G2 注意力子闸)      -> 0
行情可能已提前走完     (G2 已发酵子闸)      -> 0
★★★利空否决          (G1)                -> 0
防买顶否决            (G2 整体)            -> 0
拥挤度黑名单（…）      (G3)                -> 0
```

**正对照是必需项**：没有 `吸筹观察 → 12`，前面五个 0 有两种解释（未触发 / reason 根本不落盘）。
有正对照才能排除后者 ⇒ 结论是**样本期未触发**，**不是结构性不可达**。

⚠️ **此结论后被第三轮复核细化**（§4.1 #1）：正对照只能排除「reason 不落盘」这一竞争解释，

## 7. 方法学附注

1. **能机械化的验证才叫验收。** 反过来也成立：**不能写成 grep 的验收条件，等于没有验收条件。**
   本轮的 `R-B2 ⊆`（方向不一致）与 `R-B5 全项目`（作用域过宽）正是"写不成 grep 的判据"——
   它们看起来是验收红线，实际是文档叙事。
2. **错误的传播不认条目号。** 逐条核质询只能验证"报告点名的那 16 处改对了没"；
   拿**字面碎片**回扫才知道同一句话在文档里被复制了几遍（实测 #5 传播 9 处、跨 3 份文档）。
3. **层式文档的固有代价**：每份文档都有一段"其他层摘要"，摘要一旦写错就会在 N 份文档里各错一遍，
   而改的时候没人记得回去改摘要。本轮 §2 的 13 处里，**7 处是跨层转述行**。
4. **修订本身是新的错误来源**（§4 三处），且新错误与旧错误**同型**（计数不同步 / 算术错 / 转述漏改）。
   故「改完再独立复核一遍」是流程必需项，不是保险。
5. **「两轮够了」是本轮被证伪的判断。** §6 曾以「边际收益已很低」为由跳过第三轮，
   而第三轮抓到 6 处、含 1 处中危（§4.1）。**根因**：前两轮都是「拿**已知**错误形态回扫」，
   而 §4.1 #1 是**修订动作新产生的**、#2/#3 是**引用的分范围与字面变体** ——
   已知形态的集合不包含「修订自身产生的新形态」，所以回扫扫不到。
   ⇒ **复核轮次的终止条件不应是「感觉收益低」，而应是「上一轮的修改本身已被独立核对」。**
6. **但递归必须终止，靠的是「爆炸半径」而不是轮次。** 第 5 条的终止条件形式上会无限递归：
   核对 §4.1 → 产生 §4.2 的编辑 → 又要核对 §4.2 ……。实际数据：
   §4.1 改了**四份文档的判据与清单**（D 层 753→773 = **+20** 行、B 层 590→599 = **+9** 行、C 层 739→739 就地改写；
   度量口径：`Get-Content .Count`，与 §2 各轮同基准，可复算）；
   §4.2 对四份文档只改了 **1 行**（D 层 `:195` 的行号区间，**就地替换、行数不变**），其余全部落在台账自身。
   当一轮对**交付物**的改动收缩到个位数行、且不触碰任何判据与计数时，
   剩余风险已低于核对成本 ⇒ 可停。**判据是「改动半径」，不是「感觉收益低」**——
   后者正是第 5 条证伪的那个错误判据，不能在本条里偏又把它请回来。
