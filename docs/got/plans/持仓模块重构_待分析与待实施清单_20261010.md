## 二、待分析议题（大改前先定口径，逐条只列问题不给方案）

1. **持仓的真相源是谁**：`PortfolioService`（与 webui 共享，P1-1 兜底时因它被共享而只敢改消费侧）↔ `accounts[0]` 与 `total_equity` 口径不一致（OPEN-1 **W3**，5 处）↔ 论点/埋伏快照表。买入记在哪、卖出凭什么、多账户与外币如何归一——不定这个，任何 sizing/止盈都是空中楼阁。
2. **入场锚从哪来**：`ambush_position_snapshots` 0 行的根因是"买了的票不在埋伏池"（backlog §1.A 复核结论），那**是否需要一张通用的"每笔买入都有入场锚"表**？它同时决定 `days_held`、真 HWM、事件锚退出（P4）与 T1-H 的目标筛选能不能用。
3. **退出判据的分层**：硬止损 / 生命期阶段 / 事件解决 / 家族见顶（FTS 层A 已接 `sector_exposure_limits` 死链的教训）/ 移动止盈 —— 谁是主锚、谁只是兜底，是否允许“多判据各自 reduce”叠加。※ **重排这套分层时，`mature_reduce_shadow` 的盘点三态必须一并重定义——见 §六「大改返工钩子」，不得只改判据不改观测。**
4. **板块出名单后的持仓归属**（T-2）：继续按最后一次标签、按家族锚点（`_family_relay_match` 已有中继）、还是明确标"无信息"退回硬止损-only？
5. **近似口径的纪律**：凡输入缺失只能近似时，是「标注 + 允许动作」（现状）还是「近似只观测」（建议方向之一，需拍）。
6. **可成交性与执行**（GATE-1）：跌停/一字板卖不掉是 A 股退出策略的一等约束，目前 0 读数；它应与止盈/断点同一层设计还是独立投影层。

## 四、局限（读本文时必须知道）

1. 持仓侧样本极稀：10 月归档里**持仓观测行合计仅 2 条**（同一只票两日）⇒ T-1 的"必然误触发"是由公式反推 + 两日实例支撑，**不是统计结论**；`hwm_gain≈176%` 属反推值（`1/((1-dd)(1+pnl))-1`），非归档原值（正是 T-3 说的问题）。
2. 1008 那次 `approx=False` 而 1009 `approx=True`，但快照表现存只有 1 行（10-09）⇒ 1008 当时用过的入场来源现不可考（可能被同票 UPSERT 覆盖），**不要把"近似占比"读成 1/2**。
3. 开关读数只统计"字段非空"，未验证其内容质量；`20260917/portfolio_decision.json` 是半截损坏文件（backlog §8 #11），离线复算须容错。
4. 本文不评估 C-B4（事件锚定时标）的归属——它的锚重建工件与结论在【总计划】§4.2 C-B4，属"评价口径"而非持仓动作，暂不动。

## 六、大改返工钩子（改本模块时必须连带重做的观测面）

> 为何单开一节：持仓侧观测字段是“先埋度量、后做大改”的产物。大改一旦动了它们的**输入前提**（真相源/入场锚/生命期来源/账户形状），字段就会静默失真或语义错位——比“没埋”更险，因为它还会继续产出可读的数。下表每一项都已在线，**改对应主体时必须同步重做，并在 `../verification.md` 就地更正语义**。

| 钩子 | 它依赖什么 | 什情况下会失效 | 已锁它的东西 |
|---|---|---|---|
| **WI-P-6 `mature_reduce_shadow` 三态**（`{hits, holdings_seen, skipped_reason}`） | `accounts[0].positions` 形状 + `_score_holdings` 被调与否 + `14<day≤30` 窗口 | ① §二.1 统一真相源后若不再从 `accounts[0]` 取仓 ⇒ `holdings_seen`/`no_accounts` 判定需重写；② §二.3 重排退出分层或 §二.4 定 T-2 口径 ⇒ 窗口与 `lifecycle_day` 语义变，三态需重定；③ 多账户下“持仓数”本身变复杂 ⇒ 单计数不够 | `tests/test_mature_reduce_shadow_probe.py`（5 例，含三态与 schema 形状）；verification.md 影子五线表已定稿语义 |
| **WI-P-2/3 四个观测字段**（`hwm_gain`/`hwm_approx`/`entry_source`/`lifecycle_phase_source`） | 现在靠 `thesis_map → ambush_snapshot_map → none` 三级定 `entry_source` | §二.2 若新建“每笔买入都有入场锚”的通用表 ⇒ `entry_source` 枚举需重列（否则永远报 none），`lifecycle_phase_source` 同理随 §二.4 结论变 | 字段断言含在 trailing-stop / phase2 套件；无专门守卫（大改时补） |
| **T-1 近似 HWM 的 no-op 规则**（WI-P-1：`and not hwm_approx`） | “近似 ⇒ 不动作”的纪律决定 | §二.5 若改判为“标注 + 允许动作”或引入真入场锚 ⇒ approx 分支本身可能消失，该规则应退役而非留着堵止盈 | `test_approx_hwm_deep_loss_noop`（含 approx=False 对照） |
