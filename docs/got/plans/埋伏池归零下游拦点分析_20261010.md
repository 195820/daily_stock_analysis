## 一、三句话结论

1. **不是门槛拦的**：1009 全库 50 条事件里 43 条 confidence ≥ 0.7（86%），且 `macro_rule` 恒 1.0、`global_map` 恒 0.8（硬编码常量，门槛对它们**恒真**）；全天"有事件却被 0.7 拦下"只有 **1 例**（钠电池，narrative 0.60 档）。
2. **是事件供给的板块宇宙和埋伏名单根本不相交**：映射表 13 条覆盖 33 个板块（科技/半导体/券商为主），与当日 16 个名单板块的**静态精确交集只有 2 个（有色、黄金）**；`llm_narrative` 覆盖 34 个板块，与名单精确交集 **1 个**；`macro_rule` 10 条事件的 `affected_sectors` **全为空**，只带单个 `sector`（券商/银行）。
3. **剩下的损耗在板块名口径**：事件侧写的是「贵金属 / 有色金属 / 黄金概念」，名单侧是「黄金 / 黄金概念 / 有色」——能不能挂上取决于 `board_aliases` 变体与 glue 补桥，桥不动的板块就成了"零事件"。当日 16 个候选：**2 个名称直查命中 + 3 个靠 glue 补挂救回 = 5 个有事件，11 个整条链路零事件**。

## 二、事件→板块映射的四层链路（代码位置）

| 层 | 位置 | 做什么 | LLM 参与 |
|---|---|---|---|
| L0 入库定板块 | `catalyst_calendar.py::_full_build`（`:267`，`confidence=1.0`）/ `_map_global_events`（`:412`，`confidence=0.8`）/ `_llm_extract_narrative_catalysts` + `_parse_llm_narrative`（`:652`，`confidence` 由 LLM 自报，缺省 0.5） | 三条源各自写好 `sector` / `affected_sectors` | 仅 narrative |
| L1 分桶 | `aggregator.py::_group_events_by_sector`（`:3083`，`affected_sectors or [event.sector]` + normalize 去重） | 建 `{板块名: [事件]}` | 否 |
| L2 查表 | `aggregator.py::_lookup_sector_events`（`:3097`，精确 → `board_aliases` 变体 → 空） | 候选板块取自己的事件 | 否 |
| **L3 glue 补挂** | `aggregator.py::_supplement_from_relations`（`:3185`，开关 `GOT_AMBUSH_RELATIONS_WIRING` 缺省 on） | **仅 L2 落空时**用 `board_code` 反查 `glue.relations` | **是（A6 转正的 glue）** |

护栏（`:3192` docstring）：只信当日日历事件原值、relation 自报 `negative` 不补、**relation 自报 confidence 不作数**，下游 `CATALYST_CONFIDENCE_GATE` 照旧。
⇒ glue 只决定「能不能拿到事件」，**不决定「事件算不算合格」**；门槛分数始终来自 L0 的事件原值。

## 四、根因分层

1. **供给面：两个宇宙互相不知道对方在选什么。** 埋伏名单来自 Node 2 技术通道（吸筹/回落），事件来自 Node 4（宏观规则 + 海外映射表 + LLM 叙事）。映射表是**静态 13 条**，其板块集合与名单的当日交集只有 2 个 ⇒ 「埋伏赚事件催化的钱」这一设计前提在名单为周期/消费类时**结构性不成立**。
2. **口径面：`affected_sectors` 的词表不是 Node 2 的板块词表。** 一例即明：金价事件 `sector='黄金概念'`、`affected_sectors=['有色金属']`，而名单同时有「黄金」「黄金概念」「有色」——一个事件理论上可挂住 3 个候选，实际取决于别名桥接能否连上。
3. **`macro_rule` 的板块归属缺失**：10 条宏观事件 `affected_sectors` 全空，L1 退化为单 `sector` 扇出（券商/银行）⇒ 宏观催化对埋伏通道**近乎不可用**，尽管它们的 confidence=1.0 最容易过门槛。
4. **门槛面（次要）**：`CATALYST_CONFIDENCE_GATE = 0.7` 的实际作用面仅 `llm_narrative` 那 11 条（0.55/0.6/0.65/0.7/0.8）；规则类恒过。⇒ **backlog §5 的 5c 4.4「门槛校准」即便做完，也救不了埋伏池**，其影响范围需在原条目里收窄。

## 五、候选修法（三条，均未拍板）

| 方向 | 内容 | 风险 / 约束 |
|---|---|---|
| ① 板块名单与事件源**前置对齐** | Node 2 出埋伏名单时就带上"该板块有无在窗事件/事件源覆盖"的可观测字段，让名单选择感知事件供给，而非 Node 6 事后发现零事件 | 改 Node 2 通道语义（触候选池红线）；须 shadow 先行 |
| ② `affected_sectors` 改用单一板块词表 | 事件入库侧的板块名对齐 Node 2/`normalize_sector_name`/`board_aliases` 口径（含 macro 类补扇出） | 会改变历史事件的可比性；与既有「板块归一化」口径需协调，禁第二套口径 |
| ③ 扩映射表的板块覆盖 | 为周期/资源/消费类增加海外驱动→A股板块条目 | 属内容扩张非结构修复，条目越多越易误挂；且 13 条静态表本身的维护性已被质疑 |

> 三条都**不是**"把 0.7 门槛调低"。调门槛只影响第 4 层，且 OPEN-D3 取证已显示 confidence 对兑现质量无实质区分度、OPEN-D10 的 `direction` 语义污染（162/464 = 35%）尚未修——在污染的分值上标定更不可信。

## 六、局限（不写清就是假读数）

1. 主证据是**单日（1009）+ 一日对照（1008）**，埋伏名单日间轮换剧烈，跨日稳定性未验。
2. 1009 09:11 那次是冻结生效的跑，但其归档已被同日 13:55 的跑**覆盖**（`archive` 按日覆盖写，backlog §8 已登记该缺陷）⇒ 本文用日志取冻结生效事实、用归档取覆盖结构，两者非同一 run。
3. 探针的板块名匹配（精确 + 子串）**弱于生产的 code/别名口径**，故"零事件 11 个"以生产 `relations_supplement` 计数为准（14 落空中 10 个 relations 也没命中），探针仅用于定位名字形态。
4. `macro_rule` 的 `affected_sectors` 全空是**当日归档观测**，未核全部历史日；`sector` 单值扇出是否在部分日期有值，需扩大样本再定。
