## Summary

对 9 个竞品联网调研后与 GOT 现有代码逐项比对，确认真实缺口并按风险排布 7 个补强批次（A-G）。所有改动遵循项目既有惯例：**影子模式先行（只落观测不改决策）、宽进严筛（新增信号进评分乘数而非硬 AND 闸门）、纯增量字段带默认值保归档与老库向后兼容、转正需人工改默认值（等同签核）**。

## 批次 A：证据链与出处

### A1. Schema + DB 扩展
- `src/got/schemas.py`：
  - `NewsEvent` 新增：`source_url: Optional[str] = None`、`evidence_tier: Optional[str] = None`（`confirmed`=公告/定点量产/订单 | `reported`=权威媒体 | `rumor`=社媒传闻）。**发布时间不新建字段**：既有 `NewsEvent.timestamp` 生产端恒空、零消费者——直接补 `timestamp` 的生产端写入（语义=新闻发布时间，采集层 `published_date` 向下透传），避免 `published_at`/`timestamp` 双口径（项目反复清理的"派生幽灵"形态）。
  - `CatalystEvent` 新增：`evidence_tier: str = "reported"`、`source_url: Optional[str] = None`。
- **DB 持久化层接线（归档 JSON 默认值兼容不足以保住语义）**：`CatalystEvent` 跨日记忆在 SQLite `catalyst_events` 表（storage.py），UPSERT（catalyst_calendar.py）与回读均逐字段赋值——新字段需：① 幂等 ALTER 迁移（套 storage.py 既有 `_migrate_*` 模板）加 `evidence_tier`/`source_url` 列；② UPSERT/回读两处接线；③ `node4_raw_news` 表无 url/发布时间列，同步加列或在回读处补。
- 全部字段带默认值 → 归档 unified.json + 老库回读向后兼容（沿用 `reason` 枚举补 `data_missing` 的既有兼容模式）。

### A2. 证据分级赋值点
- `src/got/catalyst_calendar.py`：按 `source` 字段静态映射默认 tier——`akshare_earnings`/`akshare_lockup`（交易所一手数据）→ `confirmed`；`macro_rule` → `confirmed`；`llm_narrative`/`global_map` → 由 LLM 提取时输出 tier，缺省 `rumor`。**source 字面量必须逐字对齐生产实际取值集合（macro_rule / global_map / llm_narrative / akshare_{earnings|lockup}），配单测断言"映射表键 ⊆ 实际取值集合"，防"接无源枚举=死代码"既有缺陷谱系。**
- `src/got/nodes/news_analysis.py`：现状素材行格式 `{i}. [{tag}] {title} {snippet}` **不含 url/时间**，"仅需透传"不成立。改三步确定性回连：① 素材行前缀补 `[idx|url|published_at]`；② LLM 提取输出增加 `source_index` 引用；③ 代码侧按 index **确定性回连**真实 url/时间到 NewsEvent——**禁止让 LLM 生成 URL**（防幻觉，与 catalyst_calendar 实体一致性守卫同思路）；`news_feeds.py` 各采集器补齐 url/时间向下透传（现仅采集层打分用、不入事件）。

### A3. 证据阶梯进入评分（一期只降不升，防换池）
- `src/got/catalyst_config.py`：新增「证据档→催化分乘数」表（沿用吸筹档位乘数的既有模式与防倒挂原则）：**一期 `confirmed=1.0`、`reported=1.0`、`rumor`<1.0**——akshare/macro 事件是日历存量主力，只要 confirmed≠1.0，`adjusted_score` 排序截断（aggregator 催化剂池组装处）会**当日直接换埋伏池**，这不是影子是动决策面。二期启用 confirmed 折扣前，必须先用历史归档重放对比 pool 成员变化并人工确认。
- `src/got/nodes/aggregator.py`：催化剂加分处消费乘数；`rumor` 且无 url 的事件在日志中标注 `[低证据]`（仅日志）。
- 时效：**不依赖 `timestamp` 是否回填**（上线初期绝大多数事件为空，判 None=过期会烧毁叙事通道、判 None=不过期是死分支）——以既有 `node4_raw_news.first_seen_date` 列为锚（零新字段）：first_seen 超 72h 的新闻不再作为**新**催化剂锚定（仅影响新增锚定，不改已入日历事件生命周期）；`timestamp` 缺失仅打 `stale_unknown` 观测标记，不淘汰。

### A4. 测试
- tests/ 新增离线单测：tier 映射（含"映射表键 ⊆ 生产 source 取值集合"断言）、乘数一期零变化（confirmed==reported==1.0）、防倒挂档位序断言（rumor < reported，为二期预留）、旧归档 JSON + 老 SQLite 库（无新列）回读不崩、`timestamp` 生产端写入后历史归档回读兼容。

## 批次 B：轻量反偏见层（复用 disagreement 影子模式）

### B1. 最强反方论据
- **挂载点**：glue 批量 prompt 运行时 classification 尚未产出（Pass 2 才有 `classification_map`），"只对 actionable 生成"在该点位做不到。改为：Phase 2 完成后对 actionable 板块做**一次小 LLM 调用**，输出 `counter_thesis`（"如果该板块 5 日内回撤 8%，最可能的 1 条原因"）与 `red_line_hit`（对照红线清单：无出处利好/单维高分独裁/追高位置/数据缺失档位）；token 成本入 Risks 并在转正评估中量化。
- **落点字段**：`SectorIntel` 无 `other`/自由字典字段（aggregator 中的 `other` 是中间 dict 即抛）——在 SectorIntel 新增 `counter_thesis: Optional[str] = None`、`red_line_hit: Optional[str] = None` 显式字段（带默认值保兼容），并同步归档渲染。
- **职责主次**：`red_line_hit` 为 LLM 自报，与 G 批次机械检查项重叠——定调 **G 机械判定为准**，B1 自报仅观测，二者不一致本身作为 G 的一条 warning（顺带得 LLM 校准读数）。
- 影子先行：结果落归档 + reasoning.md 末尾「🧪 影子模式观测」段（项目既有统一容器，现承载 4b/3b/4.1/T1/T1-H 五条线），**不参与排序**；`GOT_ANTIBIAS_SHADOW=1` 默认开；转正前置条件：glue status=ok 且非降级/回放日，影子期 ≥10 个交易日读数且 counter_thesis 非空率 >80%。

### B2. 镜子测试式结论强制化
- **一期不进 `decision.warnings`**：warnings 是用户可见产物（终端风险提示段/推送报告上游），而 glue 降级日（`_glue_f1_degraded` 分支）与回放日 counter_thesis 必空 → 结构性误报。一期只落观测字段；转正后若 actionable 板块 `counter_thesis` 为空，再升级为 warnings 提示（不否决）。

## 批次 C：数值双源交叉验证（抽样、非逐日全量）

### C1. 校验模块
- 新建 `src/got/data_consistency.py`（小模块，~150 行）：对**当日抽样 N=10 只持仓/候选股**做双源比对，**按可得性与口径修正**：
  - 收盘价：**用不复权原始价比对，或降级为"同日涨跌符号一致性"**——全链路取数是前复权口径（tencent/efinance/akshare 均 qfq），前复权基随最新除权回溯变动，两源更新时点不同即 >1%，阈值不可比。
  - 资金流：个股主力净流入本仓仅 `fundamental_adapter` 单源（Node 3 的 DDE 已因东财封锁摘除，`individual_main_force` 无生产者）——**无第二源则不做数值阈值比对**，改为"存在双源时做符号/量级一致性"，缺源日诚实标注。
  - 口径写进产物头（与 F2 run card 呼应）。
- 偏差/不一致 → 落 `consistency_alerts` 日志 + 归档 `consistency.json`（并接入影子观测段渲染），**不改任何决策输入**。环境变量 `GOT_CONSISTENCY_SAMPLE`（默认 10，0=关闭）。

### C2. 全局 is_stale 标志
- `stale_fields` 已存在（schemas.py DataQuality）；`_validate_data_freshness`（capital_analysis.py）**本就是模块级函数**——"提为通用工具"是搬家而非重构，成本低。Node 1/2/5 行情类取数点接入前需先探测目标 DataFrame 是否含日期列（该函数对无日期列对象返回"无法验证"，mootdx/热榜对象未必带）。

## 批次 D：持仓异动归因通道（★用户确认最高价值，P0；注意 D0 是新增取数，非零依赖）

- **D0 触发取数（本批次唯一新增数据依赖，先做）**：个股当日涨跌幅——Phase 2/持仓侧现无 `change_pct` 字段（只有 P&L 口径的 `current_price`/成本价），需新增批量行情取当日涨幅（data_provider 腾讯批量接口单次 <1s，沿用 Node 2 `get_board_quick_change` 的批量模式）；**触发口径绑定 `archive._is_bar_complete`**：15:00 前生产跑 → 标注"盘中预警口径（半截行情，尾盘跳水日可能漏触发）"，收盘后跑/历史回放 → "收盘归因口径"（防 look-ahead，与 F2 run card `point_in_time` 呼应）。个股资金流本仓无源——四维诚实降为**三维+资金维缺口标注**（板块级 `sector_flow` 方向仅作旁证）。
- 新建 `src/got/news_pulse.py`：触发=持仓股 |当日涨跌|>阈值（默认 7%，可配）；三维侦察：公司新闻=Node 4 已采集 news 池（注意 `affected_stocks` 由 LLM 稀疏填充）、板块=SectorContext、情绪=HotStock 提及（仅 top50，常不含持仓——缺口如实标注）。
- **输出结构照抄 ai-berkshire /news-pulse 实战形态**（其腾讯 -10.47% 案例验证过的格式）：
  1. 一句话归因（"这次 -X% 约 70-80% 由资金面+情绪面驱动，基本面无利空"式）；
  2. **异动归因表**：候选解释 × 估算贡献（-3%~-4%）× 置信度（高/中/低），含被排除项（"基本面恶化 0% 极高置信度排除"）——排除项与保留项同等重要；
  3. **性质判断四选一（强制）**：价值事件 / 情绪波动 / 真因不明 / 混合（带百分比分解）；**"真因不明"一期仅观测落盘**——资金无源+热榜不含持仓的现状下它很可能是主导值，直接定"最高优先级告警"会重演"告警噪声→人类不看"退化；跑两周统计占比分布后再定告警优先级（与 B1 的影子读数纪律一致）；
  4. **关键反证清单**（如"竞品同日逆市上涨→排除行业性问题"），GOT 侧可用证据：同板块其他成员涨跌、Node 3 板块资金流方向、Node 5 情绪阶段、大盘 beta（Node 1 regime）。
- 与既有机制的分工：`thesis_drift`（已存在）答"买入论点是否失效"，news_pulse 答"今天这根大 K 线是谁干的"——两者互补，pulse 结论回写 thesis snapshot 的 evidence 附注，不另建存储。**与 T1-H 持仓审查（Phase 2 Step 2.5，已是逐持仓 LLM 通道）的关系**：复用 T1-H 的 profile 与影子段渲染位；**单次运行最多 N 只（硬上限，默认 3，沿用 `AMBUSH_NOMINATION_MAX` 式惯例）**，LLM 成本入 Risks。
- 接入点：`src/got/orchestrator.py` Phase 2 完成后追加一步（try/except 不阻断主流程，与 P6 兑现检测同模式）。
- **落点**（"复用现有报告渠道"无对应设施：`trading_recommendations.md` 无消费方、通知渠道不在 GOT 链路）：独立影子产物 `news_pulse.json` 落 `data/got_daily/YYYYMMDD/`，参照 GLUE/SHADOW_T1 既有命名与归档渲染模式；推送接线（gotify 等）另立子项，不在本批范围。
- 触发口径注意（防"事后反应报道双重计算"陷阱）：归因搜索窗只取异动当日及前一交易日的新闻，禁止用事后解读报道反锚原因（catalyst_calendar 事后反应纪律同源）。
- `GOT_NEWS_PULSE_ENABLED=0` 默认关，先手动跑一周验证输出质量。

## 批次 E：Lite 手动档 + 回放扩展 + 采集效率（一期不改决策面）

## Risks & Mitigations

- **归档体积/LLM token 膨胀**（v3.5 情报膨胀教训）：新字段仅按需输出；B1 改 Phase 2 后 actionable 二次小调用，token 成本入转正评估；D 单次运行最多 3 只持仓（硬上限）
- **乘数引入评分倒挂/换池**（既有陷阱谱系）：A3 一期 confirmed=reported=1.0 只降不升；二期任何 confirmed≠1.0 需历史归档重放 pool 成员对比 + 人工确认；单测断言档位序
- **双源比对自身被限流/口径不可比**：抽样 N 可调、默认 10，全部走 em_get 限流；失败静默跳过并计数；跨源比较仅用不复权原始价或符号一致性
- **影子转正失控**：每批转正条件写入代码注释与环境变量默认值，转正需人工改默认值（等同签核）
- **lite 改决策面**（计划内最高行为风险项）：一期仅手动+预检观测；自动降级延后到 lite/full 历史差异读数产出后，`GOT_LITE_MODE` 默认 0
- **回放污染生产态**（E2）：replay_mode 护栏（跳影子落盘/快照写入）+ as_of 化 + 临时库，三前置缺任一不开工；backlog #6a 翻案先登记

## Rejected Alternatives

- **66 评委/多大师角色扮演会诊**（UZI/ai-berkshire）：LLM 成本与延迟不可接受，且与"板块→个股短线"决策颗粒度不匹配；其反偏见精华已由批次 B 低成本吸收；但其"建议必须引用命中的具体规则"纪律被 G 批次吸收（每条告警必须带证据值）
- **跟单/声誉/模拟盘平台**（AI-Trader）：GOT 是单机日频分析器，非交易平台
- **实盘执行与人工审批流**（OpenAlice Trading-as-Git）：项目边界为"输出建议"，天然满足 anthropics 人类签核治理线，无需引入审批机制
- **461 alpha 因子库与策略 DSL**（Vibe-Trading）：GOT 范式为催化剂+资金流驱动，非因子驱动；仅吸收其回测过拟合检查纪律（批次 F）
- **统一数据接入层重构**（OpenBB）：data_provider 多源 + em_rate_limiter 已满足，重构收益低风险高
- **新建平行催化剂/论文追踪日历、新建独立回放入口**：catalyst_calendar、thesis snapshot、`main.py --got-replay` 均已存在，一律原地扩展
