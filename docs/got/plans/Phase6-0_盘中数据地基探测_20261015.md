**接口 2.2**：`client.minutes(symbol='600519', date='20261014')` — 历史分时序列  
**返回**：240 行 × 3 列（同上 schema）

**接口 2.3**：`client.bars(symbol='600519', frequency=8, offset=10)` — 1 分钟 K 线  
**返回**：10 行 × 13 列 DataFrame（`open`, `close`, `high`, `low`, `vol`, `amount`, `year`, `month`, `day`, `hour`, `minute`, `datetime`, `volume`）

**样本**：

**返回**：5 行 × 13 列（同上 schema，验证接口正常）

**结论**：
- ✅ `minute()` 返回当日完整分时序列（240 行 = 4 小时 × 60 分）
- ✅ `minutes(date=...)` 返回历史分时（可回放）
- ✅ `bars(frequency=8)` 返回 1 分钟 K 线（OHLCV + datetime，可直接接入技术指标）
- ✅ 粒度覆盖：分时（1 分钟点）/ 1 分钟 K / 日线，满足盘中实时 + 历史回放双需求

**OPEN-I3 更新建议**：

### 探测 4：盘中调度能力

**现状**：`main.py --got` 为日频一次性运行（收盘后跑 Phase 1 + Phase 2），无盘中定时调度能力。

**技术方案对比**：

| 方案 | 可行性 | 优点 | 缺点 | 适用场景 |
|------|--------|------|------|----------|
| **Windows 任务计划程序** | ✅ 可行 | 零依赖、原生支持、可配 9:26/11:25/14:45 定时触发 | 需手动配置（或 `schtasks` 命令行注册）、错过不补跑、日志需额外配置 | 固定时点触发、无需复杂逻辑 |
| **Python schedule 库** | ✅ 可行 | API 简洁、可内集成、支持多时间点 | 需进程常驻（`while True: schedule.run_pending()`）、需外部守护（systemd / Windows 服务）、需 `pip install schedule` | 灵活盘中逻辑（如多阶段流水线） |

**OPEN-I5 更新建议**：
> **技术方案明确**。两种方案均可行，建议：
> - **短期（Phase 6-0 验证期）**：手动运行脚本验证数据可行性，暂不实施自动调度
> - **中期（Phase 6-1 实施期）**：优先 **Windows 任务计划程序**（零依赖，适合固定时点触发 9:26/11:25/14:45），备选 Python schedule（如需更灵活的盘中逻辑）
>
> 实施细节：
> 1. Windows 任务计划程序：`schtasks /create /tn "GOT_Intraday_926" /tr "python main.py --got --intraday-time 09:26" /sc daily /st 09:26`
> 2. Python schedule：`schedule.every().day.at('09:26').do(run_got_intraday)` + 进程守护（Windows 服务或第三方库 `pywin32`）
