#### 选项 a) `PortfolioService.get_portfolio_snapshot` 增聚合口径参数

## B3 thesis 生命周期状态机定稿

### 现状

`holding_thesis_snapshots`（[`src/storage.py:1260-1290`](../../src/storage.py)）只有：
- `is_open: Boolean`（布尔，True=持仓中 / False=已卖出）
- `drift_watch_since: Date`（可空，漂移观察起始日）
- `drift_family: String(64)`（可空，观察时的家族名）

**无显式状态机**。`is_open` 无法区分「论点仍成立」与「论点已破但尚未卖出」；`drift_watch_since` 是时间戳而非状态。

### 候选状态集（至少四态起步）

| 状态 | 语义 | 进入条件 | 退出条件 |
|---|---|---|---|
| `intact` | 论点仍成立（板块未漂移或漂移但家族仍强） | 买入时 | 板块漂移且家族走弱 → `drift_watch` |
| `drift_watch` | 漂移观察中（板块已漂移但家族仍强，宽限期内） | `intact` + 漂移检测 + 家族仍强 | ① 家族走弱 → `thesis_broken`；② 宽限期内回归 → `intact` |
| `thesis_broken` | 论点已破（家族走弱或硬止损触发） | `drift_watch` + 家族走弱 / 硬止损 | 卖出 → `closed` |
| `closed` | 已卖出（正常退出） | `thesis_broken` + 卖出执行 | — |

### 迁移路径

1. **Schema 改动**：`holding_thesis_snapshots` 加列 `lifecycle_state: String(20)`（枚举：`intact` / `drift_watch` / `thesis_broken` / `closed`），`is_open` 保留但降级为派生字段（`closed` ↔ `is_open=False`）。
2. **状态转换逻辑**：在 `_score_holdings` 的漂移检测分支（`_drift_action_with_grace`）中写入状态转换（现只有 `drift_watch_since` 时间戳，改为显式状态机）。
3. **数据迁移**：现有 1 行 thesis 记录需回填 `lifecycle_state`（根据 `is_open` + `drift_watch_since` 推断初始状态）。
4. **消费点改写**：`_load_holding_theses` 返回的 thesis 对象需含 `lifecycle_state` 字段，下游退出判据（硬止损 / 生命期阶段 / P4 / FTS / HWM）按状态分支。

### 未定稿前 C4 只留接口位

**thesis 生命周期状态机定稿是 Phase C4 的前置**（[实施计划](GOT三问架构裁决_实施计划_20261015.md) Phase C 开头声明）。未定稿前，C4（trade_plans 表 + thesis 状态机接线）只留接口位（`lifecycle_state` 字段预留、状态转换函数签名预留），**不在 C4 实施中顺手定口径**。

## B4 退出判据分层（Q-exit）

### 既有五层判据枚举

| 层 | 判据 | 定位 | 代码位置 |

### 主锚/兜底关系提案（不预设结论）

**候选方案 A**：硬止损 + P4 + HWM 为主锚（直接触发卖出），生命期阶段 + FTS 为兜底（仅触发 reduce 或降档）。

**候选方案 B**：硬止损为唯一主锚（其他四层均只触发 reduce / 降档 / 观测），P4 / HWM / 生命期 / FTS 均为兜底（叠加 reduce 不叠加卖出）。

**候选方案 C**：按板块角色分道——主线仓以硬止损 + 生命期为主锚，埋伏仓以 P4 + HWM 为主锚，FTS 对所有角色均为兜底。

**推荐倾向**：**候选方案 C**（按角色分道）。理由：主线仓与埋伏仓的买入逻辑不同（主线追趋势 / 埋伏追催化），退出判据应匹配各自的持有目的。

**但最终结论归负责人拍板。**

## B5 名单归属（Q-list）

### 三选（引[持仓文档](持仓模块重构_待分析与待实施清单_20261010.md) §二.4）

**问题**：板块出名单后（被踢出 `confirmed_sectors` / `active_mainline`），持仓归属如何判定？

#### 选项 a) 最后标签

- **实现**：持仓继续按最后一次板块标签归属（即使板块已出名单）。
- **成本**：零改动（现状）。
- **影响面**：T-2 缺陷持续（[持仓文档](持仓模块重构_待分析与待实施清单_20261010.md) §〇 T-2）——板块出名单后 `lifecycle_phase` / `lifecycle_day` 断供，依赖生命期的退出判据（mature 减仓、late_stage、加速末期降档）结构性空转。

#### 选项 b) 家族锚点 `_family_relay_match`

- **实现**：板块出名单后，通过 `_family_relay_match`（`portfolio_decision.py` 已有中继匹配逻辑）查找该板块所属家族，若家族仍强则持仓归属家族（继承家族的生命期/强度）。
- **成本**：中。需改写 `_build_extended_lifecycle_map` 与 `_score_holdings` 中的板块→强度映射逻辑，增加家族中继分支。
- **影响面**：解决 T-2 断供问题，但引入家族级联依赖——家族走弱时持仓归属再次悬空。

#### 选项 c) 明确无信息退回硬止损 only

- **实现**：板块出名单后，持仓标为「无信息」（`lifecycle_phase=None`），退出判据只剩硬止损（层 1），其他四层（生命期 / P4 / FTS / HWM）全部 no-op。
- **成本**：低。需在 `_score_holdings` 中增加「板块出名单」分支，显式跳过生命期/P4/FTS/HWM 判据。
- **影响面**：保守侧（避免基于过期信息的误判），但可能过早触发硬止损（失去生命期/HWM 的缓冲）。

### 推荐倾向

**倾向选项 b)**（家族锚点中继）。理由：① `_family_relay_match` 已有现成逻辑（Fix 3: 构建家族→锚点映射）；② 解决 T-2 断供问题；③ 家族仍强时继承生命期是合理语义（板块漂移但家族趋势未变）。

**但最终结论归负责人拍板。**
