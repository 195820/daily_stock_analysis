### 1.2 核心缺陷：相位判定只读象限，不读衰减速度

`sector_analysis.py` 生命周期相位分配（`_quadrant_to_phase`，约 L2898）：

```python
_quadrant_to_phase = {
    "leading": "acceleration",
    "improving": "launch",
    "weakening": "mature",
    "lagging": "late_stage",
}
phase = _quadrant_to_phase[rrg.quadrant]
```

象限不变 → 相位不变 → `classification` 保持 `actionable`。但"加速末期"的本质是**象限内部动量的崩塌速度**，这个量（DB `node2_sector_trends.rrg_momentum_ema`；归档 `sector.json` 里另存未平滑的 `rs_momentum_raw`）系统已逐日计算，却没有任何买入侧消费者。

## 三、概念澄清：加速末期 ≠ bear

两轴正交，互不蕴含：

| 轴 | 判定依据 | 性质 |
|---|---|---|
| 板块生命周期（acceleration/mature/late_stage） | RRG 截面象限 | 板块间**相对**强度 |
| 大盘 regime（bull/transition/bear） | Node1 四维技术评分 + crash_override | 大盘**绝对**状态 |

代码互不引用；实证反例双向成立：

- **bear 日照样有 acceleration 板块**：9/28–9/30 Node1 全 bear（attack_power 0.15），红黄酒 99.0/A、创新药 87.8/A、银行 86.3/A 全部 acceleration——防御板块在熊市里照样"加速"。
- **transition 日照样有衰竭板块**：9/23 半导体 acceleration day4 但 mom_raw 0.92→0.81、强度距峰值 98.7 已回落 29%。

**推论**：不能单靠 bear 闸门拦截加速末期买入。bear 只覆盖"大盘确认恶化"的子集；transition 日的板块内部动量崩塌需要独立信号。

## 四、修复方向 v1（最小改动：动量衰减率进买入侧扣分）

> ⚠️ **v1 接线点已被 §七 复议推翻**：把 decay_2d 扣分接在 `_lifecycle_priority_score` 的 priority 上，经数学核算（§7.1）对本案例只能把 `buy_trend` 降到 `buy_dip`（仍是买入建议），且 composite 虚高到 85+ 时降一档连 buy_trend 都保不住——与历轮补丁同病：都在加法结构外围软降权，被 `0.4×composite` 托底抵消。§七给出 v2（action 层硬降级 + 仓位缩放）。以下 v1 内容保留作诊断记录，信号定义（decay_2d）仍被 v2 复用。

### 4.1 信号定义

`acceleration` 相位内，`rrg_momentum_ema` 两日衰减率：

```
decay_2d = (mom[t] - mom[t-2]) / mom[t-2]   # mom = node2_sector_trends.rrg_momentum_ema
```

- 数据源：`rrg_momentum_ema` 逐日连续落 `node2_sector_trends`（全量板块 × 每交易日），线上可直接取 t-2，零新增数据依赖。**不用归档 `sector.json` 的 `rs_momentum_raw`**——归档是分类桶快照、板块进出稀疏（如 880952 归档仅 11/47 天在档），raw 亦未落 DB（勘误见 §1.3）。
- 阈值候选：衰减 ≤ -30% 降一档、≤ -50% 降两档（初值，须回测校准）。

### 4.2 接入点

`_lifecycle_priority_score`（`portfolio_decision.py:2368`）acceleration 分支内加扣分：

```
acceleration + decay_2d ≤ -0.30 → priority 65→45（跨入 mature 档）
acceleration + decay_2d ≤ -0.50 → priority 65→20
```

- 符合 §1.4 纪律：可配参数 + 观测，不写死确定性规则。
- 仅扣分不否决（宽进严筛惯例），`UnifiedScoringResult.reasoning` 标注「动量崩塌，加速末期特征」。

### 4.3 前置：回测验证区分度（阻塞项，不得跳过）

按 §3.5 同等前置纪律：**任何接线前必须先在真实票池证明信号对前向超额有区分度**。

- 样本：47 归档日（20260724–0930）× 全板块 `node2_sector_trends` RRG 序列。
- 口径：§1.1 正确前向 + 减基准（881100 / 中证1000 双基准），T+5 / T+10。
- 假设检验：acceleration 相位且 decay_2d ≤ -30% 的板块后续超额是否显著为负；对照组为 decay_2d > 0 的 acceleration 板块。
- **证真才接线；证伪则归档为已知局限，不强行修**。

### 4.4 边界与不做的事

- 不改 `_quadrant_to_phase` 相位分配本身（避免波及 Node2 全下游：状态机、P4、P5、家族裁剪）。
- 不动 RRG EMA 平滑参数。
- 不处理 launch 相位（样本少，另议）。
- overheat §3.5 修复（解绑 D7–D9 与 price_near_peak）与本项**互补但不合并**：前者治"高位背离失明"，本项治"回落初期动量崩塌"，接线与否各自独立回测。

## 七、修正方案 v2：MEG 动能衰竭门（Momentum Exhaustion Gate）

> 本节替代 §四 v1 的接线点。核心改变：**从 priority 软扣分 → action 层硬降级 + 仓位缩放**，绕过 `0.4×composite` 托底。信号定义（decay_2d）复用 §4.1，学术依据见 §7.2。

### 7.1 v1 接线点复议：为什么 priority 软扣分压不住（数学证明）

action 判据（`portfolio_decision.py:3856`）：

```
final_score = 0.6 × priority + 0.4 × composite_score
buy_trend: final_score > 60 且 phase ∈ {launch, acceleration} 且 capital_ok
buy_dip:   final_score > 50 且 capital_ok
watch:     else
```

用本案数据（9/23 聚灿光电 composite=73.4、acceleration day5→priority=65、decay_2d=−34.3%→v1 降一档 priority=45）：

| 状态 | priority | final_score | action |
|---|---|---|---|
| 现状 | 65 | 0.6×65+0.4×73.4 = **68.4** | buy_trend |
| **v1 降一档** | 45 | 0.6×45+0.4×73.4 = **56.4** | **buy_dip（仍买入）** |
| 压到 watch 需 | ≤34 | ≤50 | watch |

- v1 对本案例实际效果 `buy_trend → buy_dip`，用户仍会买、仍接盘；要压到 watch 需 priority≤34，而 −34% 只触发降一档到 45，**够不着**。
- **托底效应**：composite=85 时，v1 降一档 final=0.6×45+0.4×85=**61 仍是 buy_trend**，v1 完全失效。composite 越虚高越压不动，而"加速末期"最危险的正是前期暴涨、composite 被 tech(0.25)+sector(0.25) 推到 85+ 的票。
- **根因**：v1 与历轮补丁（Step2 day降档 / Step3 capital gate / Step4 overheat半幅 / sentiment−10）同在 `0.6×priority+0.4×composite` 加法结构外围做软降权，**无一触及 L3856 `phase∈{launch,acceleration}` → buy_trend 这根硬链接**。只要相位不翻（§4.4 明确不改 `_quadrant_to_phase`），软扣分必被 composite 托底抵消——这就是"几轮压不下去"的数学本质。

**结论**：修复必须落在 **action 判定层**（直接改 action，绕过 final_score）+ **仓位层**（classification 缩放），而非 priority 层。

### 7.2 学术依据 → 设计原则映射

| 论文 / 方法论 | 核心结论 | 对本方案的约束 |
|---|---|---|
| **Daniel & Moskowitz (2016, JF)** Momentum Crashes | 动量崩溃**可预测**，高发于"动量近期极强、刚跑赢大盘"之后 | 越前期暴涨的 acceleration 越危险；引入"距动量峰值回撤"作辅助判据 |
| **Barroso & Santa-Clara (2015, JFE)** Momentum has its moments | 动量风险时变可测，波动率缩放削峰 | 用仓位缩放而非二元清仓（层 3） |
| **Moreira & Muir (2017, JF)** Volatility-Managed Portfolios | 高波动时降仓产生大 alpha、提升 Sharpe | classification `actionable→caution`（仓位 40%→12%），**非** exclude |
| **de Kempenaer RRG 方法论** | RS-Momentum **领先** RS-Ratio；应按"移动方向"而非"当前位置"判定；象限本身有滞后期 | 相位判定必须引入 RS-Momentum 的**方向/速度**，不能只读象限符号（层 1 核心） |
| **二阶导 / PGamma / Triple-Derivative** | 拐点在**二阶导变号**（velocity>0 但 acceleration<0 = "Bull Weakening"），远早于一阶导 | decay_2d 本质是 rs_momentum 的一阶导 = 价格的二阶导；**符号优先于幅值** |
| **LuxAlgo** Trend Exhaustion | 衰竭是"**停止加仓、开始保护**"的非对称信号；需多信号累积确认 | 只降 buy_trend（不反向、不清持仓）；连续 N 日确认降噪 |
| **Minervini** Stage Analysis / SEPA | 只在 Stage 2 买入，Stage 2→3（派发）过渡即停手 | `snap` 态 = Stage 2→3，停止 buy_trend |

**一句话**：RRG 的精髓本就是"用 RS-Momentum 领先预警拐点"，而现有 `_quadrant_to_phase` 只读象限**位置**、丢掉了**方向**——MEG 是把 RRG 方法论里被丢掉的领先维度补回来。

### 7.3 层 1 信号层：动能衰竭三态（Node 2, `sector_analysis.py`）

板块分析时查询 `node2_sector_trends` 最近 3 日 `rrg_momentum_ema`（DB 连续序列，非归档稀疏 raw），计算并落三态：

```
mom      = rrg_momentum_ema[t]
mom_1d   = rrg_momentum_ema[t-1]
mom_2d   = rrg_momentum_ema[t-2]
decay_2d = (mom - mom_2d) / mom_2d                 # §4.1 已定义
peak_dd  = mom / max(rrg_momentum_ema[t-N:t]) - 1    # 距近期动量峰值回撤（Daniel-Moskowitz）

momentum_state:
  snap   (断裂)  ← decay_2d ≤ -0.30  或  (mom<mom_1d 且 peak_dd ≤ -0.40)   # 加速末期
  stall  (滞涨)  ← mom < mom_1d 但未达 snap                               # RRG Weakening 语义
  thrust (推进)  ← mom ≥ mom_1d                                           # RRG Leading 且动能向上
```

- 三态对应 RRG 的 Leading→Weakening 过渡与 PGamma 的 Γ↑→Γ⌃→Γ↓。
- 写入 `SectorDetail.momentum_state` + `rs_mom_decay_2d`（新增字段），透传至 `SectorIntel`。
- **零新增外部数据**：`rrg_momentum_ema` 已逐日连续落 DB `node2_sector_trends`，线上取最近 3 日即可（raw 仅在归档 `sector.json`、稀疏且未落 DB，弃用）。

### 7.4 层 2 接线层：非对称降级门（Node 6, `portfolio_decision.py:3856` 后）

（`momentum_state`/`decay_2d` 从 `sector_intel_map[stock_sector]` 取，与 L3815 `lifecycle_phase` 同源）

```python
# ── MEG 动能衰竭门（v2）：直接改 action，绕过 final_score 托底 ──
# 学术依据：LuxAlgo 非对称原则 + Minervini Stage 2→3 + RRG 动量领先
_meg_on = os.getenv("GOT_MOM_EXHAUST_GATE_ENABLED", "0") == "1"
_meg_mode = os.getenv("GOT_MOM_EXHAUST_MODE", "shadow")  # shadow/veto
if (
    _meg_on
    and lifecycle_phase == "acceleration"
    and momentum_state == "snap"
    and action == "buy_trend"          # 非对称：只拦最激进的买入
):
    if _meg_mode == "veto":
        action = "watch"               # 硬降级到"不买"，不经 buy_dip
        base_reasoning += f" [MEG动能衰竭门: RS-Mom两日断裂{decay_2d:.0%}, buy_trend→watch]"
    else:  # shadow：仅留痕，不改 action（上线前观测命中率/假阳性）
        base_reasoning += f" [MEG影子: 本应 buy_trend→watch, RS-Mom断裂{decay_2d:.0%}]"
```

**为什么 v2 压得住而 v1 压不住**：v2 直接把 `action` 判为 `watch`，**与 composite_score 无关**——composite 虚高到 90 也照降。这是"质变到不买"，不是 v1 的"从激进买降到逢低买"。

### 7.5 层 3 仓位层：波动率管理式缩放（Node 2 classification）

```
if phase == "acceleration" and momentum_state == "snap" and GOT_MOM_EXHAUST_SIZING == "1":
    classification: actionable → caution    # 仓位 40% → 12%（portfolio_decision.py:371-374）
```

- 依据 Moreira-Muir / Barroso-Santa-Clara：高风险时**缩放暴露**而非清仓，保留"衰竭是警告非判决"的容错（LuxAlgo）。
- 与层 2 叠加：即便个股因其他原因仍入选，仓位系数也被砍到原来的 30%（base 0.40→0.12）。

### 7.6 参数与护栏

| 环境变量 | 缺省 | 含义 |
|---|---|---|
| `GOT_MOM_EXHAUST_GATE_ENABLED` | 0 | MEG 总开关 |
| `GOT_MOM_EXHAUST_MODE` | shadow | shadow（留痕）/ veto（生效） |
| `GOT_MOM_EXHAUST_DECAY` | −0.30 | decay_2d 断裂阈值 |
| `GOT_MOM_EXHAUST_PEAK_DD` | −0.40 | 距动量峰值回撤辅助阈值 |
| `GOT_MOM_EXHAUST_CONFIRM` | 1 | 连续确认日数（降噪，防单日假摔） |
| `GOT_MOM_EXHAUST_SIZING` | 1 | 是否联动 classification 降仓 |

护栏：
- **只对 acceleration + buy_trend 生效**：launch 早期豁免（动量刚起、样本少，§4.4 一致）；不动 buy_dip/watch/hold/sell。
- **非对称**：不做空、不清持仓（区别于退出侧 C 工作流）。
- **与 regime 正交**：transition 日照样生效（本案痛点正是 transition 日，bear 闸门够不着）。
- **影子先行**：先 shadow 观测命中率与假阳性率，达标再切 veto（沿用项目惯例）。
- **连续确认**：`CONFIRM` 日连续断裂才触发，规避单日截面噪声（LuxAlgo"多信号累积"）。

### 7.7 数据流与实施步骤

### 7.8 回测验证（阻塞项，沿用 §4.3 纪律，不得跳过）

- 样本：47 归档日（20260724–0930）× 全板块 `node2_sector_trends` RRG 序列。
- 口径：正确前向 + 减基准（881100 / 中证1000 双基准），T+5 / T+10。
- 假设检验：`acceleration + snap` 板块后续超额是否显著为负；对照组 `thrust`。
- **v1/v2 增量对比**（本方案特有）：统计 snap 板块中 `composite>80` 的占比——这批是 v1 压不住（降一档仍 buy_trend）、v2 能压住（硬降 watch）的**增量拦截**，量化 v2 相对 v1 的收益。
- **假阳性审计**：snap 后 T+5 仍正超额的板块占比（"衰竭是警告非判决"的代价），据此校准 `CONFIRM` 与阈值。
