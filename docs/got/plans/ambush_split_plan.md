## 一、总纲

**单管道 + 埋伏消费分支**（决策 1）。

- 市场级节点（Node 1/3/4/5）数据只跑一遍，主线与埋伏共享——不存在"埋伏专属的大盘"
- 埋伏只在**板块级**拆出独立通道：Node 2 技术闸门 → Node 6 埋伏评分 → Node 7 仓位/退出 → Phase 2 选股
- 埋伏赚的是**事件催化的钱**（决策 2）：前瞻事件决定"埋哪个"，技术吸筹决定"何时埋"
- 事件锚承担三重角色：**筛选器 + 持有信念 + 退出纪律**——直接根治核心痛点
  （痛点：埋伏在低位被反复磨，磨到心态崩了割肉，然后看着它飞。
  病因 = 没有兑现时点；解药 = 催化剂给出明确的兑现日期与纪律性退出点）

## 三、分节点设计

### Node 1（大盘）→ 埋伏：仅极端闸门（决策 7）

- 平时埋伏不消费 Node 1 任何输出（埋伏与大盘状态正交）
- 仅当 `attack_power < 0.25`（暴跌/深度熊市）时：**暂停新埋伏入场**
- **场内已埋伏持仓不受影响**——Node 1 只有权拦门口，无权动场内；
  退出只能由事件兑现/落空触发（防止复现"被震出去然后卖飞"）
- 注：Node 1 无"预测"字段，不新增大盘预测（Node 4 日历已是唯一前瞻锚，避免双前瞻源打架）

### Node 2（板块）→ 埋伏：只出技术闸门（决策 12、14）

DAG 物理约束：Node 2 看不到 Node 4 日历（并行路）、也看不到 Node 3 资金（下游），
因此埋伏的完整评分链路不可能在 Node 2，Node 2 只做技术层。

重构 `_is_ambush_candidate`（`src/got/nodes/sector_analysis.py`），保留 5 条、砍 1 条：

```
埋伏技术闸门 = AND(
  rrg.rs_ratio_ema < 0.55,          # ① 截面低位（保留，闸门核心）
  rrg.rs_momentum_ema >= 0.5,       # ② 动量转正（保留）
  动量"刚"转正（前日 <0.5）,          # ③ 排除已改善多日的迟到板块（保留）
  _check_ambush(df, indicators),     # ④ 结构吸筹：近3日不跌+量能≥1.3x+加权≥0.5（保留）
  strength_score <= 72,              # ⑤ 上限保留；★ 45 下限砍掉（主线尺子偏见残留）
  not is_defensive,                  # ⑥ 与防守轮动正交（保留）
)
```

- 砍 45 下限的理由：深度蓄势板块在主线尺子上天然低分，"够弱才值得埋伏"与
  "不能太弱"自相矛盾；①②③ 已保证"低位且转好"，垃圾板块过不了②
- 输出：「埋伏技术候选名单」（pass/fail + 技术证据），供 Node 6 埋伏通道消费
- 主线评分与主线框逻辑完全不动

### Node 3（资金）→ 埋伏：吸筹式消费（决策 8）

- 埋伏与主线要的资金信号**方向相反**：主线找启动（大单突增），埋伏找吸筹（温和连续）
- 确认条件：**连续 3 日小幅净流入**（消费 `sector_flow` / `dde`）
- **DDE 突然放大 = "已启动、毕业出埋伏池"**（兼作状态迁移信号，转主线逻辑处理）
- 不消费市场级 `institutional_attitude`（那是 Node 1 闸门的职责）

### Node 4（消息）→ 埋伏：新增板块级催化剂日历（决策 3、3-续、4、5、18）

**口径**：结构化骨干 + LLM 增强（选项 B）。

| 事件来源 | 方式 |
|---------|------|
| 财报披露日历、业绩预告 | akshare 结构化抓取（可回测） |
| 限售解禁日历 | akshare 结构化抓取（偏利空，用于排雷） |
| 宏观数据日历（PMI/CPI/社融/LPR） | 高度可预测，规则内置 |
| 叙事型催化（政策会、发布会、海外风向标） | LLM 补充，**强制输出日期+来源+置信度**，低置信不入评分 |

**输出形态**：板块级结构化日历（选项 A）——
每个埋伏候选板块 → `[{日期, 事件, 影响等级★, 利好/利空, 类型标签, 置信度, 共识预期, 来源}]`

- **四问 Schema**（来自用户提供的《未来两周全球股市重大事件前瞻》指南 V1.0）：
  必然发生 / 可能发生 / 影响多大 / 市场预期
- **共识预期为必填字段**（文献：量化的事件才漂移，不可量化的反转）
- **前瞻窗口 = 2 周（10–15 个交易日）**，与埋伏持仓周期绑定，不写死

**事件→板块映射：双轨制**（决策 4）：

- 结构化事件（财报/解禁/宏观）→ **规则映射**（成分股归属反查，复用问财成分股通道
  与 `TDX_BOARD_REGISTRY`，零新建基础设施）
- 叙事型事件 → **LLM 映射 + 强制置信度**，**< 0.7 不入评分**（只进日历展示标"参考"）
- 阈值 0.7 先跑，误杀率靠归档观察后调整

### Node 5（情绪）→ 埋伏：拥挤度黑名单（决策 9）

- 埋伏是**反向消费** Node 5：候选板块 constituent 上热榜 / 板块上 hot_topics
  → 排除出埋伏候选（低关注度才是埋伏的利润来源，已被全网关注 = 来晚了）
- 复用 `aggregator._extract_hot_sectors`（现成函数）
- **同步拆除 Node 6 对埋伏板块的 ±5 情绪修正**——现状 `sentiment_check=="low" → -5`
  在系统性惩罚低关注度的埋伏板块，是主线尺子偏见的实锤之一

### Node 6（聚合）→ 埋伏通道（决策 10、12、15）

在 mini-GOT Level 1 内与主线 composite **平行的独立分支**，
4 维交叉验证照做但**重新分工**，不再合成 composite：

| 维度 | 埋伏通道用法 |
|------|------------|
| 技术面 | 透传 Node 2 闸门结果（pass/fail） |
| 资金面 | 吸筹确认闸门（连续 3 日小幅净流入） |
| 消息面 | 催化剂日历消费 + 排序 + ★★★利空否决 |
| 情绪面 | 拥挤度黑名单（±5 修正已拆除） |

**评分流程（三层）**：

1. **闸门**：Node 2 技术闸门 pass + 资金吸筹确认
2. **防买顶双闸**：注意力闸（热榜）+ 价格闸（事件前抢跑幅度检查 +
   同类催化剂已在传闻期发酵过 → 拒绝；文献：等确认的人买了顶）
3. **排序（B 加权公式）**：

```
埋伏排序分 = 主催化分 + 冗余加成

主催化分 = 影响权重 × 临近系数 × 置信度
  影响权重：★★★=1.0  ★★=0.6  ★=0.3
  临近系数：事件在 3~10 个交易日内 = 1.0
           1~2 个交易日 = 0.6（anticipation 大半走完）
  置信度：原始值直乘（闸门已保证 ≥0.7）

冗余加成 = 窗口内第 2 个及以上合格催化剂，每个 +20% 主催化分，封顶 +40%

排雷前置：窗口内有★★★利空 → 直接出局
正式池规模：只收达标者，上限 10 个，宁缺毋滥（不凑数）
```

- 每个入选板块的催化剂**绑定类型标签**（漂移型=量化基本面 / fade型=软叙事 / 二元），
  直接决定 Node 7 仓位与退出策略
- 排序分唯一来源是本公式，Node 6 不做任何重排（无增量信息的重排都是噪音）

**无催化分支（决策 11）**：闸门全过但窗口内无催化剂 →

1. 先**反向查询**：以板块名+近 14 天为范围，搜技术论坛/社区/产业链讨论/小众新闻源
   （捕捉 DeepSeek 式的"行情先于公开日历"机会；复用 Node 4 search 通道与
   `lifecycle_state=emerging/fermenting`）
2. 三种结果：
   - 找到带日期的早期催化 → 写入日历；置信度 ≥0.7 直升正式池，
     <0.7 进蓄水池标"疑似早期发酵"置顶
   - 只有模糊热度、无日期无实体 → 蓄水池标"有热度未成事件"
   - 确实查不到 → 蓄水池
3. **三道防幻觉纪律**（反向查询=带着买入意图搜证据，是确认偏误温床）：
   ① 必须有来源和日期，说不出出处按"查不到"处理；② 0.7 闸门照旧；
   ③ 归档单独统计反向发现催化的兑现率，三个月后显著低于正向日历则收紧/砍掉
4. 蓄水池板块连续 **4 周**仍无催化 → 自动除名（技术结构会过期）

**矛盾否决**（决策 12）：Node 6 对埋伏只给否决权不给加分权——
日历生成后新增★★★利空 / 与日历判断矛盾的消息面 → 降入蓄水池并附理由；
否决记录进归档，用于统计否决准确率。

### Node 7（组合决策）→ 埋伏仓位与退出（决策 13、17）

**类型化仓位**：现有公式 `base × regime × role × conf` 追加催化剂类型系数：

| 催化剂类型 | 系数 | 理由 |
|-----------|------|------|
| 漂移型（量化基本面） | ×1.0（维持埋伏基准 0.55 链） | 持有吃事件后漂移，给得大 |
| fade 型（软叙事） | ×0.7 | 事件日即退，持有期短 |
| 二元/高不确定 | ×0.4，且输出显式标注"二元事件，仓位已压缩" | 文献：二元事件不要赌，赌则限仓 |

**埋伏退出分支**（扩展 `_lifecycle_sell_signal`）：

前提：**买入催化剂快照**——Phase 2 建仓时把催化剂元数据
（类型/日期/影响等级/共识预期）写入持仓记录；每日拿快照与日历/新闻对账。
快照表与归档表同一张表（买入快照 + 兑现结果 = 完整复盘记录）。

退出触发清单：

| 情形 | 动作 |
|------|------|
| fade 型催化剂 | 事件日次日开盘卖（buy the rumor, sell the news 字面执行） |
| 漂移型催化剂 | 事件兑现**不卖**，持有吃事件后漂移；满足任一退出：a. 事件后 10 个交易日漂移衰竭（板块 3 日均价走平转跌）；b. 板块破 MA20；c. 硬超时 20 个交易日 |
| 事件落空 | 到期未发生 / 宣布推迟（含星舰跳票类）→ 立即退出 |
| DDE 爆发 | 毕业出埋伏池，转主线逻辑接管 |

所有参数（10 日/20 日/MA20/4 周/0.7/各系数）进配置，归档积累后校准。

### Phase 2（选股）→ 埋伏仓选股（决策 16）

- **DDE 吸筹闸门不动**（现状：近 5 日 DDE 累计为正；个股层也不接飞刀）
- 闸门过后按**催化剂关联度重排** Top N：
  - 个股级事件（财报等）→ 当事股直接置顶
  - 产业级催化 → 主营贴合度由 LLM 判断 + 置信度
  - 置信度 < 0.7 → 不重排，保持技术排序
- 关联度只做重排不做准入（防"概念正宗但没人买"）

## 四、催化归档表（文献修订 5）

每个事件兑现后记录：预期 vs 实际、板块事件后收益、漂移方向对错、
反向发现/否决/蓄水池转化等标记。用途：

1. 所有可配参数的 A 股本地化校准源（美股文献参数不可直接照抄）
2. 反向查询通道的存废依据（兑现率统计）
3. 矛盾否决的准确率统计
4. 事件类型故事寿命的本地重估（持有窗口分型依据）

存储：SQLite（`data/stock_analysis.db`），与持仓快照共表设计。

## 核心结论（本轮实证定论，本版一切设计的前提）

> 以下两条结论已同步记入长期记忆，后续所有生命周期相关设计/复盘必须遵守。

### 结论 A：多版本混池统计陷阱——历史数据不能直接当实证样本

- **结论**：系统主线判定逻辑在 07-24~09-01 间改版 ≥5 次（08-04 个体级主线框、08-17 状态机文献校准、
  08-22 P1-P6 全链路、08-25 硬闸门消除、08-28 跨日记忆），不同版本产出的趋势数据语义不一致，
  混池统计得出的寿命分布/衰减曲线**无效**；只有现行逻辑窗口（08-28 起，仅 3-4 个交易日）内的数据可作样本。
- **证据**：CXO"14 天"轨迹中 day 值跳变（7→1→9→1→11）是历次改版计数器语义变动的化石层；
  首版全池实证（`_check_lifecycle_bias.py`）得出的"93.5% 主线 ≤7 天结束"被用户指出方法论错误后作废。
- **影响**：① 任何天数断点/折扣档位都不具备统计资格，只能作可配弱先验（决策 7）；
  ② 参数校准必须等现行逻辑下埋点积累（S5）；③ 今后对频繁改版系统做历史实证，
  先核对逻辑改版时间线划定可比窗口，再验证计数器跨状态语义。
- **适用范围**：一切消费 `node2_sector_trends` 历史数据的分析（寿命统计、阈值校准、回测报告）。
  08-17 前数据仅作连续性回填用途，禁止进入校准样本。

### 结论 B：波次重置判据——判波看回撤结构，不看状态标签和降温天数（回答"降温一天算不算二波"）

- **结论**：`wave_days` 重置条件为以下之一——
  ① 出框（cooling/exhausted）间隙 ≥2 个交易日 **且** 隙期强度低于出框前平台 ≥10 分（真洗盘再启动）；
  ② 经 neutral/ambush/defensive_rotation 退出（无条件重置，维持现行语义）。
  **单日闪断、单日深 V 一律不重置**（同波延续，落观察埋点）。
- **证据**：11 起回跳拆解——4 起真二波全部伴随 ≥2 日间隙 + ≥15 分回撤（复合铜箔 -49、焦炭加工 -47、
  煤炭开采 -38、航运概念 -15）；而状态噪声型闪断强度未回撤（种业 82→83）；
  种植业 8 个交易日在 active/exhausted 间翻转 4 次，证明状态标签不可作判波依据。
- **影响**：① 一切下游生命周期消费（折扣、续航评估、报告 day 展示）切到 `wave_days`（决策 4）；
  ② `mainline_days` 只保留"曾是主线 N 天"记忆；③ 单日深 V 的追溯改判本版不做，留埋点（决策 3）。
- **适用范围**：`_calc_wave_days` 实现、回填脚本、S3 折扣、S4 续航评估。
  阈值 2 日/10 分为 11 起样本弱先验，后续由 S5 校准；强度回撤口径升级为板块指数峰值回撤 ≥5% 列 S5 之后。

## 一、实证结论与对 momentum_bias 报告的修正

### 1.1 方法论修正（用户反馈确认）

- **历史数据混池统计无效**：07-24~09-01 间主线判定逻辑改版 ≥5 次（08-04 个体级主线框、
  08-17 状态机文献校准、08-22 P1-P6 全链路、08-25 硬闸门消除、08-28 跨日记忆），
  不同版本产出的寿命数据不可比。现行逻辑有效样本窗口仅 3-4 个交易日，
  **任何天数断点都不具备统计资格，只能作弱先验**。
- **CXO"14 天"是版本污染产物**：其轨迹中 day 值跳变（7→1→9→1→11）是历次改版计数器
  语义变动的化石层，不可作为尾部寿命样本。
- **"10-15 天见顶"启发式不被支持**：现行窗口内真正长寿命的主线几乎全部是二波拼接，
  不是连续一波。

### 1.2 二波问题（本版核心发现）

`mainline_days` 仅在经过 neutral 等非主线状态时归零；**exhausted/cooling 回归一律带着旧天数
累加**。后果：种业显示 day=9，实际 = 一波 ~4 天 + 二波 5 天的拼接值；
若照抄报告的折扣表，会给正当壮年的二波打上"老主线"折扣——方向反了。

11 起回跳事件的间隙结构拆解（4 起真二波 / 7 起噪声）：

| 类型 | 特征 | 案例 |
|------|------|------|
| 真二波 | 间隙 ≥2 日 且 隙期强度跌破出框前平台 ≥15 分 | 复合铜箔(-49)、焦炭加工(-47)、煤炭开采(-38)、航运概念(-15) |
| 状态噪声 | 间隙 1-2 日，强度未回撤甚至走高 | 种业(+3)、石墨烯(-3) |
| 单日深 V | 间隙 1 日但强度深回撤（截面口径，可信度低） | 粮食概念(100→78→100)、水产品(-21)、百货(-38)、种植业(-25) |

**结论：判别波次的不是"降温几天"，而是回撤结构。**

### 1.3 附带暴露的数据质量问题

1. **幽灵记录**：库中存在 `'CXO概念\x00'`、`'创新药\x00\x00'` 等带 NUL 字符的重复板块行，
   独立积累轨迹，污染寿命统计与趋势查询。
2. **exhausted 状态抖动**：种植业 8 个交易日在 active/exhausted 间翻转 4 次；
   化纤在 exhausted 停留 7 天但强度 82-83。状态标签不可作为波次边界依据。
3. **过热检测历史从未真正触发**（既往复盘）：主线多以急跌破位结束，
   续航评估必须把破位风险列为独立信号，不能只看过热分。

### 3.2 wave_days 波次计数器（S2，依赖 S1）

1. **Schema**：`Node2SectorTrendRecord` 新增三列——
   `wave_days INTEGER DEFAULT 0`、`wave_start_date DATE`、`wave_peak_strength FLOAT`。
   迁移复用 `_migrate_node2_sector_trends` 的 PRAGMA→ALTER 幂等模式。
2. **计算**：`_calc_wave_days`（紧邻 `_calc_mainline_days`）：
   - 前日 active_mainline → `prev.wave_days + 1`，`wave_peak_strength = max(prev_peak, today)`
   - 前日 cooling/exhausted → 按决策 2 判据：间隙不足 2 日或无实质回撤 → 冻结继承（同波）；
     否则重置 1 并更新 `wave_start_date`
   - 前日非主线族状态或无记录 → 重置 1
3. **回填**：`scripts/backfill_wave_days.py` 按时间序全量重算（幂等可重跑）。
   注意：08-17 前数据为旧逻辑产物，回填值仅作连续性需要，不作为校准样本。
4. **输出**：`SectorDetail` 新增 `wave_days` 字段；`LifecycleInfo.days_since_launch` 保持不动（兼容）。
5. **埋点**：`_save_sector_trends` 写库后，额外追加一行到 `data/wave_calibration.jsonl`
   （{date, sector, wave_days, strength, wave_peak}），次日运行补齐前日记录的板块涨跌幅，
   供 S5 校准。

### 3.3 生命周期折扣（S3，依赖 S2）

   - `portfolio_decision.py`：持仓所属家族进入"见顶风险期"→ 注入 `PortfolioDecision.warnings`
   - `main.py` 控制台展示该节（同现有轮动信号/拥挤警告的呈现模式）
4. **边界**：本模块不修改任何买卖决策路径，仅展示 + warnings；下游是否消费由 Phase 2 既有逻辑决定。

### 3.5 校准机制（S5，与 S3/S4 并行，依赖 S2 埋点）

- `scripts/calibrate_wave_coeff.py`：读 `wave_calibration.jsonl`，按 wave_days 分箱输出
  次日强度变化均值 / 板块涨跌幅均值 / 下跌占比，给出折扣档位建议值。
- 触发节奏：埋点积累 ≥40 个交易日后首次运行；此后每月一次（对齐 `reports/param_calibration_*.md` 惯例）。
- 强度回撤 10 分阈值后续升级为**板块指数峰值回撤 ≥5%**（K 线事实，需在 `_calc_wave_days`
  引入板块 K 线查询）——列为 S5 之后的独立小版本，不阻塞本版。

## 六、假设与未决项（显式留痕）

1. 阈值 2 日/10 分/折扣档全部来自 11 起样本的弱先验，S5 校准后仅改配置不动逻辑。
2. 单日深 V 的追溯改判（V 后 2 日站不稳 → 重划波次起点）本版不实现，先留埋点。
3. 强度回撤是截面百分位口径，可能被其他板块集体上涨"挤"出假回撤；
   板块指数价格回撤锚点升级在 S5 之后。
4. 报告建议 2/3/4/5（双轨排名、加速度优先、催化驱动引入、乘法模型）不在本版范围，
   逐项处置与搁置理由见 §1.4，待本版波次口径稳定后另立计划评估。
5. 幽灵行清理涉及动库，脚本产出删除报告后须用户确认才执行删除。
